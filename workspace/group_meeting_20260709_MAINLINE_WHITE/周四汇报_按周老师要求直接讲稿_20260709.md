# 周四汇报：按周老师聊天记录整理的直接讲稿

这份稿子只围绕周老师这次聊天里的真实问题。目标是明天能自然讲出来，不把内容搞成论文答辩，也不继续堆旧实验。

## 0. 这次汇报的核心

周老师已经认可 SafeConf 这个框架，说“做得挺好”。现在要补的不是继续调公式，也不是马上做一个很花的模型比较，而是把实验设置变硬。

现在的结果主要来自 random held-out pair：在 `context × perturbation` 矩阵里随机留出一部分组合做测试。这个 setting 能说明 SafeConf 有任务风险排序信号，但难度还不够。因为每个 context 往往在训练里见过一些 perturbation，每个 perturbation 也见过一些 context。

下一步要做的是周老师最后提到的三类更难任务：

1. 只给矩阵里的一个小块，模拟训练信息很少的情况；
2. 整行、整列 holdout，分别模拟新细胞背景和新扰动；
3. 一个数据集上固定规则，到另一个数据集上预测或评估。

gene perturbation 和 chemical perturbation 都要分开看。

## 1. 明天开场怎么讲

可以这样说：

> 老师，我回去重新看了一下上次您问的点。我现在觉得关键不是继续调 SafeConf 的公式，而是要把实验 setting 补硬一点。  
>   
> 目前 SafeConf 更准确地说是 task-level risk score，也就是判断一个 context-perturbation 组合整体难不难预测。它现在还没有充分解决同一道任务上 GEARS、scGPT、CPA 哪个模型更可靠的问题。  
>   
> 所以下一步我准备先补三个 setting：小矩阵、整行整列 holdout、跨数据集。每个 setting 里我会把预测错误来自哪个模型、风险分数用了哪些输入、有没有用到测试真值，都列清楚。

这段讲完，老师会知道你听懂了他的最后要求。

## 2. 周老师的第一个问题：分数到底跟什么相关？

老师原话核心是：

> 衡量好坏的时候是跟什么 correlate 的？实际预测错误的，他用的是什么模型？

这个问题不能再模糊回答。明天要明确说：

> 我现在评价的是 SafeConf score 和 actual prediction error 的关系。这里的 error 必须绑定具体 predictor，比如 reference predictor、GEARS、scGPT 或 CPA。  
>   
> 所以后面我会把结果表改成 predictor-level 的格式，至少写清楚 `predictor_name`、`error_metric`、`risk_score_name` 和 `split_setting`。这样不会只说“预测错误”，却没说是谁的错误。

建议之后所有结果表都带这些列：

| 字段 | 作用 |
|---|---|
| `dataset_name` | 哪个数据集 |
| `perturbation_family` | gene 或 chemical |
| `split_setting` | random pair / submatrix / row holdout / column holdout / cross-dataset |
| `predictor_name` | 哪个预测器产生预测值 |
| `error_metric` | RMSE、top-gene RMSE 或其他误差 |
| `risk_score_name` | SafeConf、support-only、context-only、disagreement-only、predicted magnitude |
| `association_metric` | Spearman、partial Spearman、top-k enrichment、AURC |

## 3. 第二个问题：disagreement 本身用了模型输出

老师原话核心是：

> 第三个指标其实就是跑了一些 model，然后看他们之间的区别。这样你的分数就不是针对每个 model 来说的。

这个地方要承认，不能绕。

可以这样讲：

> disagreement 这一项确实用了模型输出。它的含义不是“某一个模型一定不可靠”，而是“多个预测器对同一道任务分歧很大，说明这道任务整体更难”。  
>   
> 所以我现在把 SafeConf 主张放在 task-level risk triage，也就是任务层面的风险分诊。至于 model-specific reliability，比如同一道任务上 GEARS 和 scGPT 哪个更靠谱，我会放到后续实验里单独做。

这里的边界要讲清楚。你越主动，老师越不容易继续卡你。

## 4. 第三个问题：magnitude / 最后一个值到底怎么算？

老师反复问：

> 最后一个值是怎么算的？输入的东西是什么比较重要。你要保证输入的东西是你没见过的东西。

这其实是在问有没有泄漏。尤其是 magnitude 这里，现有材料里容易混。

要拆成两类：

| 名称 | 能不能前置使用 | 解释 |
|---|---|---|
| `true effect magnitude` | 不能 | 它来自真实扰动后的表达变化，只能事后用来控制混杂 |
| `predicted magnitude` | 可以 | 它来自预测器输出，可以作为前置风险 baseline |

明天可以这样说：

> 我这里要重新整理一下输入来源。true effect magnitude 不能作为 prospective risk score，因为它需要真实实验结果，只能用来事后控制混杂。  
>   
> 真正可以部署的是 predicted magnitude，也就是模型预测出来的效应向量长度。后面我会把每个 score 的输入来源列成表，区分训练 fold、control 表达、预测输出和测试真值。

这一步很重要。它直接回应老师“是不是得先测出来才能知道大不大”的疑问。

## 5. 第四个问题：当前 random held-out pair 还不够

你现在已有的 random pair 可以保留，但要承认它只是第一层。

可以这样讲：

> 目前 random held-out pair 是第一层验证。它证明 SafeConf 在普通留出组合上有风险排序信号。  
>   
> 但这个任务相对温和，因为 context 和 perturbation 通常都在训练中见过一部分。所以下一步我会补更难的 split。

## 6. 下一步实验一：小矩阵 / 低覆盖度

对应周老师说的：

> 只给这个矩阵的其中一个小矩阵。

实验想法：

在 `context × perturbation` 矩阵里，只让模型或风险评分系统看到一个小块。比如只暴露 25%、50%、75% 的组合，然后在剩余区域上评估 SafeConf 能不能把高错误任务排出来。

| 项目 | 设计 |
|---|---|
| 名称 | E34 submatrix difficulty ladder |
| 训练信息 | 只给一个 context 子集 × perturbation 子集 |
| 难度 | 25%、50%、75% 覆盖度 |
| 测试 | 小矩阵外的 held-out pair |
| 指标 | Spearman、top-k enrichment、AURC |
| 目的 | 看训练信息减少后，SafeConf 是否仍能排序风险 |

明天可以这样讲：

> 这个实验主要模拟参考知识不完整的情况。训练矩阵越小，任务越难。如果 SafeConf 在低覆盖度下仍能把高错误任务排前面，这个证据会比 random pair 更有说服力。

## 7. 下一步实验二：整行 / 整列 holdout

对应周老师说的：

> 有整行整列的 hold out。

这里要拆成两种：

| 子任务 | 含义 | 考验什么 |
|---|---|---|
| 整行 holdout | 留出整个 context / cell line | 新细胞背景下，context similarity 是否有用 |
| 整列 holdout | 留出整个 perturbation / drug / gene | 新扰动下，support 线索会不会失效 |

明天可以这样讲：

> 整行 holdout 对应新细胞背景。这个时候如果有 control 表达，context similarity 仍然可以算。  
>   
> 整列 holdout 更难，因为新 perturbation 没有历史支持量，support 可能为 0。chemical 可以考虑结构指纹，gene 可以考虑 gene embedding 或通路信息；如果暂时没有这些，就要把它作为冷启动边界写清楚。

这一段能显示你听懂了“不是所有特征在所有 setting 里都能算”。

## 8. 下一步实验三：跨数据集预测

对应周老师说的：

> 在一个数据集上，比如所有都见过了，但是在另一个数据集上来预测。

这个实验最难，不建议一开始就跨 gene 和 chemical 混做。先同类之间转移。

| 方向 | 优先级 | 理由 |
|---|---:|---|
| gene → gene | 高 | 生物任务更接近 |
| chemical → chemical | 高 | 可以连接 Tahoe、Srivatsan、McFarland |
| gene → chemical | 低 | 机制差异太大，容易变成解释不清的负结果 |

明天可以这样讲：

> 跨数据集我先不打算一上来做 gene 到 chemical。更稳的是同一类型内部先做，比如 gene 数据集之间、chemical 数据集之间。这样如果结果不好，也能判断是跨数据集泛化问题，而不是任务类型完全不同造成的。

## 10. 如果老师追问，怎么答

### 10.1 “你这个分数到底能不能用于没做过的实验？”

可以答：

> 可以，但要看 score 的输入来源。context similarity 可以用 control 表达；support 只能用训练 fold 里的历史扰动记录；disagreement 和 predicted magnitude 可以用预测器输出。true effect magnitude 不能用于前置打分，只能用于事后分析。

### 10.2 “那两个都没见过怎么办？”

可以答：

> 如果 context 和 perturbation 都完全没有任何可用表征，那 SafeConf 当前版本确实很难判断。这属于冷启动边界。  
>   
> 但如果有 control 表达、gene embedding、chemical fingerprint 或通路信息，就可以把完全没见过的对象映射到已有空间里。这个可以作为后续扩展。

### 10.3 “你现在的分数是不是只是在说任务难？”

可以答：

> 是的，当前主张就是任务层面的风险分诊。它先回答哪一些任务更容易错。模型级可靠性需要另外做同一任务下多模型预测记录，比如 GEARS、scGPT、CPA 的同任务比较。

### 10.4 “magnitude 比你强怎么办？”

可以答：

> magnitude 是强 baseline，我会并列报告，不会回避。SafeConf 的价值主要看它在控制 magnitude 后是否还有额外风险信息，以及在不同 setting 里能不能稳定用于高风险任务分诊。

### 10.5 “这三个 setting 都要做吗？”

可以答：

> 我建议先做输入来源审计，再做小矩阵和整行整列。这两个最直接回应上次的问题。跨数据集难度更高，可以作为第二轮，但会提前把数据兼容性和可计算性查清楚。

## 11. 明天最后可以这样收尾

> 老师，我下一步不打算继续盲目加实验数量，而是先把 setting 补完整。  
>   
> 第一周先做输入来源审计，确认每个 score 是否能在 held-out 任务上前置计算；第二步做小矩阵和整行整列 holdout；如果这两类结果稳定，再做 gene 和 chemical 内部的跨数据集评估。  
>   
> 如果这条线能跑通，SafeConf 就不只是 random split 上的相关性结果，而是能说明在更接近真实使用场景的情况下，它仍然可以做任务风险分诊。
