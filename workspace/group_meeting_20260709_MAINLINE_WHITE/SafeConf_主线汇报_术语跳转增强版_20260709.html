02
BIOLOGICAL TASK

从生物问题说起：我们到底在预测什么

这页给不熟悉单细胞的人看

单细胞组学

把很多细胞逐个测量，而不是只看一管细胞的平均值。每个细胞会有自己的 转录组 状态。

扰动

对细胞施加基因敲除、药物或刺激，观察 表达谱 如何变化。

效应向量

把“扰动后表达 - 对照表达”写成一个向量；模型预测的就是这个变化方向和大小。

04
RECORD CONTRACT

为什么一直强调 PredictionRecord：它让模型比较不再糊

这页解释 E20–E32 这串工作的共同目的

一条 PredictionRecord 至少要说清

数据集、任务、预测器、split、gene panel、predicted effect key、true effect key、误差。没有这些字段，后面所有比较都会变成口头说法。

strict validator 的意义

这个检查有实际用途：防止把不同基因空间、不同 true effect、不同 split 的结果硬拼到一张表里。

字段人话解释如果缺失会怎样
gene_panel_id这条预测用了哪一批基因。两个模型可能根本不在同一空间比较。
true_effect_key这道任务对应的真实效应向量。同一任务下不同模型可能用了不同真值。
split / fold训练、验证、测试的划分。容易发生 leakage，结论看起来虚高。
run_typesmoke 还是 formal。会把工程冒烟测试误写成正式实验。
05
RISK SIGNALS

SafeConf 看哪些风险线索：四盏灯，各有边界

术语都可点开看解释

背景相似度

新任务像不像训练中见过的细胞背景。越陌生，越容易出错。

历史支持量

同类扰动在训练历史中出现得多不多。支持少，风险高。

模型分歧

不同预测器对同一任务意见差多少。分歧大，值得复核。

效应幅度

真实生物效应越大，模型越可能难。它是强基线，必须正视。

讲法：这些线索不是彼此替代。SafeConf 的价值在于把它们放进同一个分诊框架，并明确什么时候失效。

SafeConf

本项目的方法名。它位于表达谱预测之后，负责判断哪些任务更可能出错。

汇报说法：SafeConf 是预测后的质检层，用来安排人工复核和湿实验优先级。

回到汇报 ↑

单细胞组学

把每个细胞单独测量，而不是只看一堆细胞的平均值。这样能看到细胞之间的差异，比如不同细胞系、状态或反应强度。

汇报说法：我们的任务发生在单细胞尺度，context 很重要。

转录组

一个细胞里哪些基因正在被转录、表达量大概是多少。单细胞转录组常用一个很长的基因表达向量表示。

汇报说法：扰动预测通常就是预测转录组状态如何变化。

细胞背景 / context

任务发生的细胞环境，比如细胞系、细胞类型、时间点、状态。相同药物在不同细胞背景下可能完全不同。

汇报说法：SafeConf 的一个核心线索是新 context 是否像训练历史。

扰动 / perturbation

人为施加的改变，可以是基因敲除、药物、细胞因子、感染刺激等。模型要预测细胞被扰动后会怎样。

汇报说法：任务就是 context × perturbation 的组合。

表达谱

一组基因的表达量列表。可以理解为细胞当前状态的一张“读数表”。

汇报说法：预测模型输出表达谱变化，SafeConf 判断这个输出是否值得优先复核。

效应向量 / effect vector

扰动组平均表达减去对照组平均表达。它把“扰动造成的变化”变成一个向量，方便比较预测和真实结果。

汇报说法：GEARS、scGPT 进入同一合同后，要比较的是同一 effect vector 空间。

任务 / task

一个具体的预测问题，例如“Adamson 数据里，K562 背景下敲掉 CCND3 后表达变化是什么”。

汇报说法：SafeConf 现在最稳的是 task-level risk，不是所有模型级判断。

PredictionRecord

统一记录格式。每条记录说明数据集、任务、预测器、基因面板、预测向量、真值向量和误差。

汇报说法：没有 PredictionRecord，模型比较就会变成“看起来像”，不能严肃审计。

gene panel

参与比较的一组基因。不同模型如果使用不同基因集合，误差和分歧就不能直接比。

汇报说法：E28/E29 强调 shared 512-gene panel，就是为了避免基因空间错位。

true effect

从真实数据中计算出来的扰动效应向量。它是评估预测误差的参照。

汇报说法：同一任务下不同预测器必须共用同一个 true effect key。

split / fold

把数据分成训练、验证、测试。fold 是交叉验证中的一轮划分。

汇报说法：所有风险特征都必须 fold-safe，只看训练部分，不能偷看测试。

leakage / 泄漏

测试集信息提前进入训练或特征计算。它会让结果虚高，是机器学习评估中很严重的问题。

汇报说法：E1–E4 里专门修过 outer-fold 泄漏，正式口径只用修正后结果。

strict validator

检查 PredictionRecord 是否字段齐全、key 能否找到数组、同任务真值是否一致。它像实验输出的质检员。

汇报说法：strict issue_count=0 表示合同层面可审计，不代表性能一定好。

task-risk

任务本身的风险：这道 context × perturbation 是否天然难预测。它不关心具体模型 A 或 B 谁更好。

汇报说法：SafeConf 当前最扎实的结论在 task-risk triage。

model-specific risk

同一道任务上，不同模型各自的可靠性。例如 GEARS 对这个任务可信，scGPT 不可信，或反过来。

汇报说法：这是当前下一阶段缺口，E25–E32 正在打开入口。

Frozen score

预先固定公式的风险分数。公式不根据测试集调参，优点是解释清楚、可信度高。

汇报说法：Frozen 多数成立，但不是所有数据集都成功。

learned risk

用模型学习风险规律，比 Frozen 灵活，但也更容易被调参或数据划分影响。

汇报说法：learned 结果可作为扩展，不要拿它覆盖 Frozen 的失败边界。

magnitude

效应幅度。真实变化本身越大、越复杂，预测误差往往越高。

汇报说法：magnitude 是强基线，Tahoe top-10 中比 SafeConf 更强。

context similarity

新细胞背景和训练背景有多像。越像，模型越可能有经验；越不像，风险越高。

汇报说法：这是 SafeConf 的可解释风险来源之一。

historical support / 支持量

训练历史里类似扰动出现了多少次。支持量低表示模型几乎没有参考案例。

汇报说法：support 是“有没有历史经验”的量化。

model disagreement

不同预测器对同一任务输出差多少。分歧越大，说明这道任务没有共识，更值得检查。

汇报说法：E29 中 GEARS–scGPT disagreement 为弱正相关，不能夸大。

seed disagreement

同一个模型用不同随机种子训练后，对同一任务预测差多少。它可以作为模型自身不稳定性的线索。

汇报说法：E32 已跑通 fixed-test 3-seed smoke，初步正相关，但还不是正式证据。

seed / 随机种子

控制训练中随机过程的数字。不同 seed 可能导致模型得到稍微不同的参数和预测。

汇报说法：做三 seed 是为了看模型自身是否稳定。

epoch

模型完整看一遍训练数据的次数。1 epoch 常用于 smoke，正式训练通常需要更多。

汇报说法：E32 是 1 epoch，所以只能说工作流跑通。

run_type

记录一次运行是 smoke 还是 formal。E31 给 GEARS exporter 加了这个字段。

汇报说法：run_type 防止把工程测试误写成正式实验。

smoke test / 冒烟测试

小规模检查管线能不能跑通。它验证工程链路，不承担最终性能结论。

汇报说法：E27、E31、E32 都要明确是 smoke。

RMSE

预测向量和真实向量差异的均方根误差。越小，预测越接近真值。

汇报说法：风险排序常用 RMSE 作为真实错误目标。

Spearman 相关

看两个排序是否一致。风险分数越高，真实误差是否也越高，常用 Spearman 判断。

汇报说法：E32 seed disagreement ρ=0.679 是排序相关，不是误差绝对值。

partial ρ

控制一个强混杂因素后，再看两个变量的相关。这里常用于控制 magnitude 后看 SafeConf 还有没有额外信号。

汇报说法：E2 residual 和 partial ρ 是反驳“只是 magnitude”的关键。

top-k enrichment

取风险最高的 k 个任务，看其中高错误任务是否比随机更多。它贴近实际分诊价值。

汇报说法：Tahoe 中 SafeConf top-10 为 4.88×，magnitude 为 6.49×。

selective prediction

模型可以选择不回答高风险样本，或把高风险样本交给人工复核。评价重点是保留预测的平均误差是否下降。

汇报说法：SafeConf 很适合讲成 selective prediction / triage。

GEARS

基于图神经网络的基因扰动预测模型，常用于基因敲除/组合扰动预测。

汇报说法：GEARS 现在是模型级验证中最可推进的一条线。

scGPT

单细胞基础模型，使用 Transformer 思路学习细胞和基因表征。本项目已跑通 forward smoke 和 GEARS–scGPT shared 合同。

汇报说法：scGPT 已进入合同，但 formal adapter 仍需完善。

CPA / chemCPA

用于建模扰动、药物和剂量效应的条件生成/表征模型家族。当前本地还缺可直接进入 SafeConf 的逐预测向量。

汇报说法：CPA 现在只能说待审计，不能说正式接入。

adapter

把不同模型的原始输出转换成统一 PredictionRecord 的薄接口。

汇报说法：模型级比较要先统一 adapter 合同，再进入正式跑分。

Adamson

常用于基因扰动预测的单细胞数据集。本项目 E28–E32 的 GEARS/scGPT shared 和 GEARS 3-seed smoke 都在 Adamson 上推进。

汇报说法：Adamson 是当前模型级入口数据集。

Norman

另一个常用 CRISPR 扰动数据集，常包含单基因和组合扰动。

汇报说法：下一步如果扩展 GEARS fixed-test，可以考虑 Norman。

Tahoe

大型 chemical perturbation 数据。项目中 D1–D5 用于检验 SafeConf 在大规模药物扰动上的分诊价值。

汇报说法：Tahoe 给出正信号，也暴露 magnitude 更强的边界。

sciplex3

药物/剂量/细胞系扰动数据。E13–E17 把它推进到 full-743 shared drug-dose 外部验证。

汇报说法：sciplex3 是 chemical 外部验证的重要支撑。

scPerturBench / E8b

外部 benchmark 关联分析。它显示多种方法的错误与任务风险方向一致，但数据是聚合层面的。

汇报说法：E8b 支持外部关联，不等于逐预测模型校准。

E32

最新 fixed-test 3-seed GEARS smoke。在 Adamson 7 个固定任务上跑 seeds 1/2/3，合并 21 条 strict PredictionRecord。

汇报说法：E32 是正式 seed uncertainty 的工程入口，下一步要提高 epochs 和任务规模。

湿实验

真实生物实验，如重新做扰动、测序或验证候选结果。资源昂贵，不能每个预测都做。

汇报说法：SafeConf 的应用价值是把有限湿实验资源投到更可能出错或更值得验证的地方。
