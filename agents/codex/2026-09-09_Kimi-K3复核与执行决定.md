## 3. 教学材料发现的问题

### 已修正的事实错误

1. HTML 把 K562/RPE1/HepG2/Jurkat 的偏相关点估计 `0.3475/0.1407/0.3259/0.3169` 写成“区间下限”。真正下限是 `0.2475/0.0390/0.2291/0.2259`。
   证据：`docs/实验结果/E201_txpert_multitarget_retraining_20260802/formal_core_evaluation/tables/E201_PARTIAL_ASSOCIATIONS.csv`。
2. “真值有 95% 把握落入区间”不是频率学派置信区间的严格解释，已改为重复抽样覆盖含义。
3. 偏相关是控制幅度后的剩余关联，不是 SafeConf 的“独有贡献”，更不是因果效应或组合效用。
4. “当前正式结果只来自 E199、E200、E201”漏掉了正式负结果 E202，已更正。
5. “32 个模型训练中”改成“32 项已登记、当时启动数为 0、正在等待 GPU”。
6. 完成度 `40–50%`、构件 `100%/90%` 没有客观分母，已改为“已完成/部分完成/未完成”的证据状态。

### 表达和教学边界

- “每个科研名词都有解释”过度承诺。Git、JSON、CSV、PID、WoS、ISSN 等仍没有首次解释；现在改为“核心术语尽量解释”。后续若要达到全术语点击跳转，需要把正文术语链接到统一词典，不能只靠文末表格。
- “对标 Nature”只能描述白底、面板字母和克制配色，不能暗示图件或研究已经达到 Nature 标准。
- “审稿人最吃这一套”“送命项”“超过大多数”“在哄你”等措辞不适合作为长期教材，已经收敛为可核查的陈述。
- 24 张图是内嵌 SVG，浏览器阅读正常，但没有独立 SVG/PNG 文件和数值 sidecar；它们适合教学，不应直接当投稿 Figure 1–3。
- HTML 中不少证据仍是纯文本路径而不是可点击相对链接。正式学习入口已经补充，下一轮若继续改 HTML，应把每章“证据”集中做成相对链接，而不是继续扩正文。

## 4. Q1：组合排序怎样设计

不建议在完整 E201 上同时试 C1、C2、C3，再挑最好看的一个。这样会把同一批已解封真值用作模型选择和效果证明。

采用以下两级方案：

### 开发级（只用于选规则，不算外部证据）

- 输入：E201 1,808 个主任务；按 perturbation condition 分组，保证同一扰动在不同 target 的记录不跨训练/验证折；
- 主候选：`z(rank magnitude) + λ × z(rank SafeConf)`，`λ ∈ {0, 0.25, 0.5, 1.0}`；`λ=0` 明确代表幅度基线；标准化参数只从当前训练折计算；
- 备选敏感性：幅度前 30% 内由 SafeConf 重排；
- 暂不使用 logistic。只有两个特征也会因结局阈值、正则化、训练折和候选选择产生额外自由度，现阶段收益不抵审计成本；
- 评价：外层 grouped cross-validation 的 20% oracle-normalized utility、high-error capture、Spearman；选择规则和置信区间按扰动条件成簇；
- 开发结论只写“选定了待外部确认的规则”，不写“组合已经更优”。

### 确认级

- 在一套未参与组合选择的新数据或冻结的新模型家族上只运行最终规则一次；
- 同时报告幅度、SafeConf、源域离散度、冻结组合；
- 主通过门：组合相对幅度的 20% 复核效用配对差，95% 簇自助区间下限大于 0；
- 若不通过，业务 A 的结论保持“关联存在但没有证明决策增益”，不得继续在确认集调 λ。

## 5. Q2：E205 第二家族

优先候选是 TxPert Exphormer，而不是直接接 scGPT、GEARS 或 scFoundation：

- TxPert 仓库已有 `config-exphormer.yaml` 和实现 `gspp/models/pert_models/exphormer.py`；
- 它与 GAT 的扰动传播结构不同，同时仍处于同一数据模块与输出合同内；
- 当前缺少 `config-x-cell-exphormer.yaml`，因此不是“直接可跑”，应先做一个 target、一个 seed 的合同 profile，再决定是否扩为 4 target × 4 seed；
- Exphormer-MG 同时改变架构和图来源，解释变量更多，放在普通 Exphormer 之后；
- scGPT/GEARS 若不能严格复用 3,352 基因顺序、四 target 切分和相同预测端点，不应手工拼表。

若 Exphormer profile 无法满足相同任务合同，E205 登记工程失败，并把 E201 的 `family disagreement` 明确降级为同架构随机初始化敏感性。

## 6. Q3：队列监管器审查

Kimi 版本有四个会影响正式运行的问题：

1. `start_job()` 先创建 run directory，而冻结适配器明确拒绝任何已存在的 run directory；旧代码一旦拿到 GPU，首个任务会立即失败。
2. 失败后仍用原目录重试，第二次仍会被“拒绝覆盖”挡住。
3. `training_pids_for()` 虽然写了，却从未调用；监管器异常退出后，重启可能把仍在运行的训练重复提交。
4. 重启扫描会跳过标为 COMPLETE 的目录而不复验 gate；中断时也可能把未完成队列写成 COMPLETE。

本轮修正：

- 只创建 run directory 的父目录，把正式目录留给冻结适配器创建；
- 失败/陈旧目录移动到 `_failed_attempts/`，保留证据后再干净重试；
- 从日志恢复尝试次数，识别并等待断线遗留训练进程；
- 每次扫描 COMPLETE 都复验 80 轮、checkpoint、target/seed/arm、target 对应权重行数、零回退、训练集专用、零 target 真值读取及外部源码未修改；
- 状态文件每轮更新 active、detached、waiting、attempts 和失败归档；
- 每项总计最多 2 次尝试，即首次失败后最多重试 1 次；
- 收到停止信号时不杀死已启动的训练子进程，状态写为 INTERRUPTED，后续监管器接管。

回归测试：`code/safeconf_audit/tests/test_e204_queue.py`，覆盖目录创建、完整门、尝试次数恢复、失败目录留存和遗留进程识别。

## 7. Q4：证书门怎样写

同意保留原判定：`3.61e-10 > 1e-10`，正式 certificate gate 为 FAIL，下界违反数 0。不接受修改阈值后改写 PASS。

不同意现在就把原因写成“与 float32 累乘精度一致”。这是合理怀疑，还不是已经验证的原因。可以增加 float64/long-double 诊断：从封存的四种子向量与真值重新计算方差分解残差，报告不同计算顺序和数据类型下的最大残差。无论诊断结果如何，原始门仍保持 FAIL。

## 8. Q5：完成度怎样表达

不采用总完成度 40–50%。不同构件没有共同分母，百分比会制造不存在的精度。以后固定使用状态表：

## 9. 完整实验顺序

```text
修正并测试 E204 监管器
        ↓
双远程提交后重启等待队列
        ↓
32 个训练项逐项验收
        ↓
统一用冻结 checkpoint 生成盲态预测
        ↓
检查任务/基因顺序和输入哈希
        ↓
封存 checkpoint、预测、评分与哈希并双远程留痕
        ↓
按补充冻结规则一次性分析 E204
        ↓
业务 A：受限组合开发 → 冻结 → 新外部确认
        ↓
E205：Exphormer profile → 满足合同才扩为正式家族
```

E204 训练成功只支持业务 B；E205 只回答分歧的架构含义；组合外部确认才回答业务 A 是否有幅度之外的实际决策增益。三者不能互相代替。
