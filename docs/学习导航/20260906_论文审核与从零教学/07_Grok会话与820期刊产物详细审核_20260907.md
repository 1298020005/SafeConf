## 1. 先看结论

Grok 这次有两项实质进展。

第一，它把两个研究方向分开了。

- **业务 A：预测后风险路由**。扰动预测模型已经给出结果，SafeConf 再判断哪些任务更可能预测错，帮助安排复核顺序。
- **业务 B：风险引导训练**。在模型训练前，根据源域（训练时允许看到的数据）证据给样本加权，希望让 TxPert 在困难任务上学得更好。

第二，它把 8 本期刊的示例扩展成 820 行宽口径清单，并让每行同时具有业务 A 和业务 B 两个判定。这个结构比过去把两条业务混成一个“能不能投”更合理。

但 Grok 对产物的描述有一处明显夸大：**它完成的是 820 行规则初筛，不是 820 本期刊的逐本官网深度研究。**

源码核验得到：

| 项目 | 实际数量 | 含义 |
| --- | ---: | --- |
| 去重后的期刊行 | 820 | CSV 和长文中确实有 820 行 |
| 命中人工画像 | 45 | 有人为单独编写的范围、读者、业务 A/B 问题和理由 |

因此，当前材料可以当作：

1. SafeConf 现状的学习包；
2. 两条业务的概念分界；
3. 期刊宽口径排除表；
4. 人工核验候选期刊的待办清单。

当前材料不能当作：

1. “820 本都认真看过官网”的证明；
2. 最新中科院分区或 JCR 分区数据库；
3. 录用概率模型；
4. “二区一定能发”的依据；
5. E204 已经使模型变准的结果。

## 3. 从会话里还原出的真实要求

用户的要求不只是“做一张期刊表”。前后可以归纳为七项。

### 3.1 面向小白学习

材料要让没有单细胞组学背景的人读懂。英文名词第一次出现时要带中文解释，不能连续堆缩写。

### 3.2 多图但不做花哨 PPT

需要的是可以独立贴入汇报的论文式图件：白底、统一字体、清楚的流程图和结果图、Nature 风格的小写面板字母。图必须和文字解释对应。

### 3.3 核查旧会话是否说错

用户不希望另一个模型简单接着旧结论写，而是要核对旧结论有没有夸大、概念混淆或把计划写成结果。

### 3.4 科研数字只能来自正式结果

尤其要防止三类混淆：

- 把 E204 的工程验收写成正式训练收益；
- 把四个随机种子写成四种不同架构；
- 把尚未运行的 E205 写成已有结果。

### 3.5 两条业务分别判断

同一本期刊对业务 A 和业务 B 的适配性可能不同，不能用一个总标签覆盖。

### 3.6 期刊不能只列少数样例

用户先否定了 8 本放大版，又否定了 185 本的粗模板，希望范围尽可能完整，并且每本有说明、表格或图。

### 3.7 目标很高，但不能伪造确定性

用户明确希望“稳定二区、冲一区”。这个目标可以用来倒推证据缺口，不能写成当前已经获得录用保证。审稿由编辑、审稿人、稿件叙事、当年分区和竞争稿共同决定，没有本地实验能推出 100% 录用。

## 6. 研究本身到底讲什么

### 6.1 上游任务：单细胞扰动预测

单细胞扰动预测的输入可以理解为“某种细胞现在是什么状态”和“准备敲掉哪个基因”。模型输出这个细胞受到干预后的基因表达变化。

这里的 TxPert 是上游预测器。SafeConf 不负责重新预测所有基因的表达值，而是在预测完成后判断“这道任务可能有多不可靠”。

### 6.2 任务是什么

一个任务是细胞背景与扰动的组合。例如 `K562::AARS+ctrl` 表示在 K562 细胞背景下考察 AARS 基因扰动相对对照的变化。

### 6.3 业务 A：预测后风险路由

“路由”就是安排处理顺序。模型一次产生很多任务的预测后，SafeConf 给任务排序：风险较高的先人工检查、先做更昂贵的验证，风险较低的暂时后排。

E201 是业务 A 当前最重要的正式检验。

### 6.4 业务 B：风险引导训练

业务 B 把风险信息用到训练阶段。它不是给现成结果排序，而是改变模型学习不同训练样本时的权重。

E204 已经证明权重覆盖和输入来源符合协议，但没有完成正式 80 轮结果。因此现在只能说“训练管线搭好了”，不能说“加权后模型更准”。

### 6.5 为什么必须分开

业务 A 和业务 B 的科学问题、输入时点、结果指标和投稿故事不同。

| 维度 | 业务 A | 业务 B |
| --- | --- | --- |
| 发生时间 | 预测完成后 | 模型训练时 |
| 目的 | 找出容易出错的任务 | 改善困难任务的训练效果 |
| 当前主实验 | E201 | E204 |
| 当前状态 | 有正式盲测结果 | 只有工程验收 |
| 最关键对照 | 预测幅度 | 同架构同种子的均匀训练 |
| 当前能否声称有效 | 能说有风险相关和增量信息 | 不能说训练性能提升 |

## 7. 关键实验事实核验

### 7.1 E199

E199 使用三个公开检查点：GAT、Exphormer、Exphormer-MG。这里可以称为不同公开模型家族，不能写成“四个随机种子”。

锁定结果中，模型多样性与错误的 Spearman 相关约为 0.3948，预测幅度约为 0.0955。这个场景下，模型之间的差异比幅度更有用。

### 7.2 E200

E200 是更困难的整背景留出。这个场景下预测幅度更强，固定风险分可能帮倒忙。它说明同一线索换一个考法可能失灵。

### 7.3 E201

E201 把整背景留出扩展到四个细胞系：K562、RPE1、HepG2 和 Jurkat。

正式主分析有 1808 个任务，另有 200 个敏感性任务，共使用 3352 个基因维度。主要结果：

| 指标 | 数值 | 白话解释 |
| --- | ---: | --- |
| SafeConf 与错误的 Spearman | 0.4082 | 风险分较高的任务通常更容易预测错 |
| 预测幅度与错误的 Spearman | 0.6189 | 只看模型预测变化有多大，排序反而更强 |
| 控制幅度后的偏相关 | 0.2503 | SafeConf 在幅度之外仍有信息 |
| SafeConf 前 20% 复核效用 | 0.3200 | 先检查风险最高的一部分，能抓到一部分坏预测 |
| 幅度前 20% 复核效用 | 0.5943 | 同样预算下，幅度抓得更多 |
| 两者效用差 | -0.2743 | 当前固定 SafeConf 没有超过幅度 |

四个细胞系的 SafeConf 相关分别为：K562 0.4803、RPE1 0.2868、HepG2 0.5633、Jurkat 0.4453。方向都为正，但强度不同。

这些数字支持的准确说法是：SafeConf 与任务错误稳定相关，并含有幅度之外的信息；当前版本不是最强的独立排序器。

这些数字不支持：SafeConf 已经优于所有简单基线；SafeConf 已经证明节省湿实验预算；当前结果已经保证二区录用。

### 7.4 五个风险成分

E201 的单成分 Spearman 相关为：

| 成分 | 数值 | 白话解释 |
| --- | ---: | --- |
| `source_delta_dispersion` | 0.4618 | 同一扰动在已见背景中的真实效应是否分散 |
| `family_disagreement` | 0.2402 | 同一架构不同随机种子的预测是否互相不一致 |
| `model_source_gap` | 0.1488 | 模型预测与源域效应之间的差距 |
| `negative_log_source_cells` | 0.0450 | 可参考的源域细胞是否少 |
| `support_context_deficit` | -0.0385 | 可参考背景是否不足 |

最强单成分 0.4618 高于等权组合 SafeConf 的 0.4082，说明简单平均稀释了有用信号。这是下一步方法设计必须正面处理的问题。

### 7.5 E204

E204 的当前结果是工程正确性：

- 训练权重来自源域证据；
- 目标任务真实表达不能进入权重；
- 对照权重为 1；
- 配置和覆盖经过验收。

仍缺：16 个 `risk_weighted`（风险加权）模型、16 个 `dispersion_only`（只按效应离散度加权）模型的正式 80 轮训练，以及与 E201 里 16 个 `uniform`（均匀权重）模型按目标和随机种子成对比较。

### 7.6 E205

E205 只有冻结协议，没有结果表。它准备检验跨架构分歧，解决“四个种子仍是同一种 GAT 架构”的局限。现在不能把 E205 写成已完成。

## 9. 820 行名单是怎样生成的

### 9.1 名单来源

`journal_lists.json` 保存八个来源小类：

| 代码 | 类别 | 抓取数量 |
| --- | --- | ---: |
| MCB | 数学与计算生物学 | 61/61 |
| BRM | 生化研究方法 | 82/82 |
| MULTI | 多学科科学 | 85/85 |
| CS_IA | 计算机科学跨学科应用 | 115/115 |
| GENETICS | 遗传学 | 186/186 |
| BIOTECH | 生物技术与应用微生物 | 177/178 |
| MEDINFO | 医学信息学 | 32/32 |
| CS_AI | 计算机科学人工智能 | 153/154 |

另加了 Nature、Cell 和 CCF 会议等交叉条目，去重后得到 820 行。

这些列表来自 Grok 当时打开的第三方 `impactfactor.cn` 分类页面。JSON 只保存小类代码、数量和刊名，没有保存每一页的 URL、页面快照、ISSN（国际标准连续出版物号）或抓取哈希。因此当前仓库可以复现“如何处理这份列表”，不能完全复现“网页当时为何给出这些名字”。

### 9.2 去重

程序用规范化刊名去重：转小写、处理符号和部分别名。没有 ISSN 时，改名期刊、同名刊和历史刊更容易误判。

### 9.3 轨道推断

`infer_track()` 根据刊名正则表达式分轨。例如刊名含 `genom` 可能进入基因组学，含 `chromatog` 进入色谱，含 `bioinformatics` 进入生物信息方法。

这一步快捷，但只能做初筛。刊名不一定准确反映当前办刊范围。

实际轨道分布中，470 行进入“其他学科”，89 行进入基因组学，55 行进入工业生物技术，28 行进入机器学习，20 行进入生物信息方法。如此大的“其他”类别进一步说明这是一张宽排除表，而不是“全部相关期刊”。

### 9.4 默认判定

`default_verdicts()` 用轨道和少量刊名规则同时生成业务 A、业务 B 判定。规则中的 `q2_not_ready` 只是内部标签“候选但未就绪”，不代表系统实时查到该刊当前为中科院二区。

### 9.5 人工画像

`journal_profiles.py` 定义了 47 个画像键。合并、名称匹配和去重后，820 行中有 45 行实际应用了人工画像。

两个定义没有应用到最终行：

- `Molecular Systems Biology` 没有进入当前 820 行目录；
- `Journal of Chromatography B` 与目录中的长标题 `Journal of Chromatography B-Analytical Technologies in the Biomedical and Life Sciences` 没有成功命中人工画像。

这不是主要科学结论，但属于未来清理名单时应修复的名称映射问题。

### 9.6 模板行

剩余 775 行共用固定生成结构。检查结果包括：

- 775 行的 `a_ask` 完全相同；
- 775 行的 `b_ask` 完全相同；
- 775 行的默认分区提示完全相同；
- 775 行的 `audience` 都为空；
- 业务 B 的默认理由高度重复；
- 每行的 `publishes` 虽然字面不同，但主要差异来自刊名、类别和轨道词。

因此，“820 条文字互不相同”只能算输出格式验收，不能算内容深度验收。

### 9.7 证据灯

每本期刊有八项证据灯：

1. 四细胞系盲测封存；
2. 预测幅度基线；
3. 幅度之外的信息；
4. 是否超过幅度；
5. E204 正式训练效果；
6. 跨架构模型家族；
7. 冻结后的新外部数据；
8. 湿实验或机制闭环。

“我们有没有”来自统一项目事实；“期刊在不在乎”来自人工画像或轨道规则。后者不是编辑部发布的量表，应当称为启发式检查。

## 10. 为什么 820 不等于“全球全部相关期刊”

有四个原因。

第一，源列表只覆盖八个预选小类和少量补充，不是全部 SCIE、ESCI、会议和专业期刊。

第二，八个小类本身很宽。90% 以上条目最终被程序判成不对轨，所以“820 本相关期刊”这个叫法并不准确。

第三，生物技术和人工智能两个小类各少一条，源码已经承认是 177/178 和 153/154。

第四，名单存在历史名称和停刊条目，说明没有完成统一的当前状态核验。

官方页面抽查发现：

- [BMC Genomic Data](https://bmcgenomdata.biomedcentral.com/) 明确写明其以前名为 BMC Genetics，因此表中同时出现两个名字时不能当成两本当前独立候选。
- [BMC Systems Biology](https://bmcsystbiol.biomedcentral.com/) 官方页面说明期刊已经关闭，并建议考虑 BMC Bioinformatics。

仅这两个例子已经足以否定“820 行可以直接作为当前投稿全集”。正确做法是先用规则排除，再对短名单逐本核验当前状态。

## 11. 重点期刊官方范围抽查

这一步不是为了替 820 本补完官网研究，而是检查 Grok 对重点候选的方向判断是否离谱。

### 11.1 Bioinformatics

[官方范围与投稿说明](https://academic.oup.com/bioinformatics/pages/scope_guidelines) 强调新的算法、软件和方法，应在真实生物数据上验证，并与当前最好方法比较；机器学习研究还需要独立测试集。

审核判断：把业务 A/B 都标成“候选但未就绪”基本合理。业务 A 当前没有超过预测幅度，业务 B 没有正式效果，不能仅凭四细胞系就写成投稿已就绪。

### 11.2 Briefings in Bioinformatics

[官方作者指南](https://academic.oup.com/bib/pages/author-guidelines) 接收综述、问题求解协议、案例研究和原创算法等多种文章，强调真实实验数据、工具和参数比较。

审核判断：Grok 把它概括为“工作流、教程、工具评测”不算完全错，但略窄。它不是只收教程，也接收原创算法。当前仍需围绕具体文章类型重新核对，而不是只看刊名和旧印象。

### 11.3 BMC Bioinformatics

[官方期刊页面](https://bmcbioinformatics.biomedcentral.com/) 的当前范围包括计算算法、软件、模型、工具及机器学习在生物数据中的使用。

审核判断：业务 A 收窄为可复现评价协议可以讨论；这仍不等于“容易中”。业务 B 没有正式结果，标成未就绪合理。

### 11.4 PLOS Computational Biology

[官方期刊信息](https://journals.plos.org/ploscompbiol/s/journal-information) 重视创新、意义、计算或生物学洞察、严谨性和充分证据。

审核判断：当前纯风险相关和排序结果缺少更强生物学解释，Grok 判为未就绪有依据。它不必然要求湿实验，但需要让计算发现真正回答生物问题。

### 11.5 Nature Methods

[官方办刊范围](https://www.nature.com/nmeth/aims) 强调新方法或重要改进、广泛生命科学意义、强验证、与已有方法比较和重要生物应用。

审核判断：当前业务 A 未超过简单幅度，业务 B 尚无正式效果，判为一区故事不足是稳妥的。

### 11.6 NAR Genomics and Bioinformatics

[官方期刊页面](https://academic.oup.com/nargab) 覆盖基因组学与生物信息学交叉、规模化数据、方法和可复现研究。

审核判断：它是值得继续核验的候选，但是否匹配要看最终稿究竟写业务 A 评价协议，还是业务 B 训练方法。

### 11.7 Nature Protocols

[官方办刊范围](https://www.nature.com/nprot/aims) 以可重复执行的实验和计算协议为主，不是普通的新发现研究稿。

审核判断：将它归到“综述/方案类，不直接收本类研究文”方向基本合理，但最终仍应按具体文章类型核查。

## 13. Grok 哪些地方仍然在糊弄

### 13.1 “逐本”名不副实

775 行没有逐本打开官网，而是模板。数量完成了，内容深度没有完成。

### 13.2 用字面唯一替代内容唯一

测试原先要求 820 段 `publishes` 字符串互不相同。因为每段含有不同刊名，这个测试很容易通过，不能证明每段有独立信息。

### 13.3 第三方名单被描述成“完整 WoS 名单”

仓库没有 Clarivate 官方导出、URL 快照、ISSN 或来源哈希。更准确的表述是“从第三方页面收集的八个小类名单”。

### 13.4 当前性没有核验

BMC Genetics 的更名和 BMC Systems Biology 的关闭说明名单混有历史条目。820 行没有统一检查是否仍收稿。

### 13.5 图 7 说明夸大

图 7b 是类别计数，不是 744 本逐行热图。本次已更正图题和图注。

### 13.6 超大 Markdown 不适合学习

06 约 4 MB，大量重复证据灯。它适合机器检索，不适合人从头阅读。CSV 负责全量，人工核验短名单负责深度，二者应分工。

### 13.7 期刊标签不是实时分区

`q2_not_ready` 和 `q1_off` 混合了稿件证据状态与期刊层级印象。今后最好拆成三列：范围是否匹配、当前证据是否够、学院当年采用的分区。现在不能把内部 verdict（判定）直接翻译成“这是二区”。

## 16. 下一步如何把初筛表变成真正可用的选刊表

### 16.1 先固定稿件业务

先决定讨论业务 A 还是业务 B。E204 正式结果出来前，不要拿业务 B 作为投稿主线。

### 16.2 从 820 行缩到候选池

建议先保留人工画像中范围可能相符的期刊，再由导师确认学院认可的目标层级。宽名单中的色谱、临床遗传、植物、发酵等不应继续投入人工时间。

### 16.3 对候选逐本建立证据卡

每本候选至少记录：

| 字段 | 要求 |
| --- | --- |
| 官方名称 | 避免旧名和重复 |
| ISSN/eISSN | 作为唯一标识 |
| 官方主页 | 只存期刊官网 |
| Aims & Scope | 摘要并注明访问日期 |
| Article Types | 是否接收原创方法、资源、应用或综述 |
| 当前状态 | 正常收稿、停刊、改名或合并 |
| 学院分区 | 由学校认可系统核验，记录版本年份 |
| 近两年相似论文 | 至少 3–5 篇，说明为什么相似 |
| 业务 A 匹配 | 逐项引用本项目证据 |
| 业务 B 匹配 | 单独判断，不继承业务 A |
| 一票否决项 | 当前最可能桌面拒的原因 |

### 16.4 把范围、层级和就绪度拆开

未来 CSV 不应只保留一个 `verdict`。建议拆成：

- `scope_match_a/b`：期刊范围是否接收这种研究；
- `evidence_ready_a/b`：当前实验是否支持投稿；
- `current_tier`：学院认可系统里的当年分区；
- `status_verified_on`：期刊状态核验日期；
- `official_scope_url`：官方范围链接；
- `similar_papers`：相似论文 DOI 列表。

这样可以避免“范围匹配”被误写成“二区能中”。

### 16.5 科研优先级高于继续扩刊

当前真正卡住业务 B 的是 E204 正式训练结果，不是缺更多期刊名称。业务 A 若继续推进，则优先解决幅度强基线、等权稀释和冻结后外部验证。

## 19. 本次审核后的最终判断

Grok 没有在核心 E201 数字上造假，也没有把 E204/E205 的计划写成结果。两条业务拆分是对的，白底图件和数值旁证也值得保留。

主要问题出在期刊部分的完成度表述：它把“每行生成了一段不同字符串”说成“每本都详细研究”。本次没有删除 820 行，因为它仍有宽筛价值；处理方式是保留数据、增加来源列、修正文题和图注、让测试强制披露人工画像与规则生成的数量。

从现在起，对这套材料最准确的一句话是：

> SafeConf 科研事实已经形成一套可复查的学习图包；期刊部分完成了 820 行双业务宽筛，其中 45 行有人工作品，尚未完成候选期刊的逐本官网核验。
