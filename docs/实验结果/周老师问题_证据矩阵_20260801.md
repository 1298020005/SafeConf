# 周老师问题：逐项证据与下一步实验

更新时间：2026-08-01

这份表只回答周老师在最近一次讨论里实际追问的内容。`已完成`指协议和结果都已
落盘；`部分完成`指已有证据，但还不能作普遍结论；`待完成`指必须新增实验。

## 一、老师的三个核心问题

### 1. 风险分数和谁的真实误差比较

现有主实验的对象不是一个含糊的“预测错误”。每条记录都绑定
`predictor_name × task_id × error_endpoint`：

- 每个 scGPT 或 GEARS 成员有自己的 RMSE；
- `family RMS error` 是六个成员 RMSE 的平方平均后开根号；
- `worst-member error` 是六个成员中最大的 RMSE；
- `centroid error` 是六个预测均值与真值之间的误差。

模型分歧给出的是注册预测家族的 family/worst error 下界。它能说明“这组模型中
至少存在多大风险”，不能判断是 scGPT 错、GEARS 错，或哪一个 seed 错。E194 的
成员重复和合成攻击进一步证明，family 成员、权重、预测哈希必须事前固定。

E197 又把真实误差拆成绝对表达误差、去共同响应后的相关形状误差、centroid
discrimination 和 retrieval rank。同一批 K562 任务中，风险量与 effect MSE 正相关，
与 transported Pearson error 负相关；RPE1 的区间则普遍跨 0。因此以后每个风险
结论必须同时写明 predictor、误差定义、评价空间和任务单位。

状态：**已回答边界**。可以报告 family 风险，不能把分歧写成某一个模型的置信度。

### 2. 最后一个 predicted magnitude 是否偷看了真实实验

没有。E190 的实际代码是：

```text
family centroid = 六个冻结预测向量的均值
predicted magnitude = RMSE(family centroid, zero vector)
```

它只使用模型已经生成的预测 effect，不读取目标扰动后的表达。真实 effect 只在
预测文件、任务顺序、成员哈希和评价合同推送到 GitHub/Gitee 后打开，用于计算
`error`。predicted magnitude 是一个很强的简单基线，不是 SafeConf 独有特征；
E195、E196 和 chemical 实验中它经常优于更复杂的不确定性量，所以必须保留。

状态：**已回答**。严格实验可在目标真值未知时计算；旧实验只有通过输入审计后才能
进入主证据。

### 3. 一个没见过的 `(context, perturbation)` 怎样打分

需要把四类输入分开：

| 输入 | 预测时来自哪里 | 是否需要目标扰动表达 | 完全未见时怎么办 |
|---|---|---:|---|
| context similarity | 目标背景的 control 与训练背景 control | 否 | 有目标 control 就能算；没有则缺失并触发 abstain |
| historical support | 训练表中该扰动的有效记录数 | 否 | 返回 0，不能假装有历史支持 |
| model disagreement | 多个冻结模型对该任务的预测 | 否 | 取决于模型是否支持 OOD context/perturbation |
| predicted magnitude | 冻结 family centroid prediction | 否 | 只要模型能预测就能算 |
| perturbation similarity | 化学结构、基因知识图或外部 embedding | 否 | 化学侧已有 RDKit；基因侧仍需真实知识图模型 |

这里真正的限制不是 SafeConf 公式，而是底层预测器能否为双未见任务给出合法预测。
化学侧 E84/E87/E89 已用 SMILES/Morgan 指纹处理新药；基因侧当前的 STRING 分析只是
机制审计，还不是 TxPert 的重训练或正式接入。

状态：**部分完成**。输入来源已经说清；基因侧知识图预测器仍是未闭合项。

## 二、老师要求的三档难度实验

周老师最后说的三个任务可还原为：小训练子矩阵、整行/整列留出、跨数据集直接预测。

| 老师要求 | 对应实验 | 已经得到的结果 | 裁决 |
|---|---|---|---|
| 只给完整矩阵的一小部分 | E189，support=1/2/3/5 | 同一 scGPT–GEARS 家族完整运行；平均误差从 support 1 到 3 下降，到 5 基本进入平台 | setting 已闭合 |
| 随机缺格与整行、整列、双未见同表比较 | E189 genetic；E84 chemical | random pair 明显偏容易；unseen row 较弱；double-unseen 可出现负路由收益 | setting 已闭合，不能声称普适有效 |
| 一个数据集训练，另一个数据集预测 | E190 Adamson→Replogle K562；E192 →RPE1；E87/E89 chemical | 流程和防泄漏合同完整，但基因侧相对简单基线的改善很小，RPE1 经验 gate 返回 ABSTAIN | setting 已闭合，预测效能尚不是强阳性 |

所以，“三个任务都能跑”已经解决；“三个任务都表现好”没有成立。这个区别必须保留，
否则会把负结果改写成成功。

## 三、现有证据还缺什么

### 1. 新数据上的评价协议要先校准

E197 只保存目标任务 centroid，没有完整的单细胞评价对象；它没有补造预测细胞去跑
MMD、Energy 或 DE，也没有事后追加 WMSE。下一项
E198 使用 scPertEval 官方 `arch1` 数据做 `EXTERNAL_PROTOCOL_CALIBRATION`：先利用
技术重复和无信息参考检查每个指标是否真能分辨生物信号，再决定哪些端点能进入后续
模型评价。

`arch1` 是 H1 hESC、150 个 CRISPRi 扰动的公开训练 split，只有一个 context。
它能支持真实单细胞协议校准和未见扰动实验，不能单独回答整行或跨 context 泛化。
scPertEval 明确建议把 BDS 用作方向门槛；BDS 小于 0.5 的协议不可信，DRF用于衡量
有效动态范围。E198 会在打开 4.1 GB 文件前冻结协议、阈值、种子、最低细胞数和
失败规则。

### 2. 基因侧需要真正的知识图预测器

TxPert 使用 batch-matched control 和多种基因关系图，覆盖未见单基因、双基因以及
新细胞背景。它和周老师“未见扰动可由结构/关系相似性提供信息”的建议直接对应。
下一轮不能把 E147 的 retrieval 或 E144 的 STRING 失败分析称为 TxPert 复现；应从
官方公开仓库固定 commit，先核对公开图和权重能覆盖哪些任务，再决定能否与 SafeConf
形成同 predictor、同 split、同 endpoint 的比较。论文使用的 PxMap/TxMap 含专有数据，
公开版本能做到的范围必须单列。

### 3. 强基线和多指标不能省

PerturBench 2025 报告没有一个架构普遍最好，简单模型具有竞争力，rank 能补充 RMSE；
2026 年的 in-the-wild benchmark 又显示 unseen context、unseen perturbation 和
cross-dataset 下性能显著下降，指标变化还会改变模型排序。后续正式表至少保留：

- zero effect；
- train/source mean；
- batch-matched control；
- predicted magnitude；
- retrieval/rank；
- 通过 E198 校准门槛的绝对、方向和群体端点。

## 四、接下来的执行顺序

1. **E198：arch1 外部协议校准。** 冻结后才第一次打开文件；输出每个协议的 BDS、
   DRF、逐扰动正负对照、运行资源和独立复算。
2. **E199：arch1 未见基因扰动。** 只使用训练扰动和 control 生成预测与风险，主要
   端点只能从 E198 通过的协议中事前选择；结果打开后不换指标救结果。
3. **E200：TxPert 可复现性与接入审计。** 固定官方代码版本，区分公开 STRING/GO
   与不可公开 PxMap/TxMap；不具备的组件直接记为 unavailable。
4. **E201：同 outcome 比较。** 若 TxPert 能合法产生目标任务预测，再比较注册 family
   证书、TxPert 模型内信号、magnitude 和简单基线；若输出合同不一致，不做伪横评。
5. **新增多 context 数据。** 优先使用 scPertEval 的 Replogle K562/RPE1 与
   Nadig HepG2/Jurkat 形成共享扰动的跨背景矩阵；原始 H5AD 只放数据盘，Git 只保存
   URL、大小、SHA-256 和解析清单。
