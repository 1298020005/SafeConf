# E233：修复 Jiang24 上游线性预测器的训练—推理合同

执行前登记，2026-09-23。E208五个模型训练完成，但潜变量架构和线性架构在封存验证集均未超过无变化基线，测试扰动表达读取0行。

## 确定的代码问题

冻结的PerturBench提交 `c84038bc1ea409aa54f3832cfa6f34f5059adf0c` 中，`LinearAdditive.training_step` 和 `validation_step` 将 `batch.gene_expression` 同时作为模型控制输入和监督目标，没有使用 `SingleCellPerturbationWithControls` 已提供的 `batch.controls`。推理阶段的反事实数据集却把对照表达放入模型输入。该训练—推理合同不一致使E208线性结果不能作为合格上游预测器证据。潜变量模型使用了 `batch.controls`，不受这个具体代码错误影响，但它自己的能力门仍失败。

E233不改外部仓库，不覆盖E208结果；在本仓库新增子类，只改训练和验证的控制输入为 `batch.controls`，目标仍为 `batch.gene_expression`。预测方法沿用上游实现，因为反事实推理数据的 `gene_expression` 本来就是目标背景对照。

## 两个预登记变体

1. `matched_control_softplus`：修复控制输入，保留发布配置的softplus非负输出。
2. `matched_control_linear`：修复控制输入，同时关闭softplus，使模型严格实现“对照表达 + 扰动偏移”。

两个变体均只先训练种子1，使用完全相同的Jiang24训练/验证切分、优化器超参数、批大小2000、最多400轮和早停耐心50。GPU0和GPU1各运行一个变体。不得根据训练中间曲线改变超参数。

## 验证与后续

训练结束后，在原216个验证任务、12个细胞—刺激背景上评价。只有平均任务MSE严格低于无变化基线，且至少8/12背景不劣于无变化，才允许选为合格上游候选。若两个均通过，按验证平均MSE选择一个，并冻结选择记录；随后补种子2–4并重新运行架构均值能力门。只有最终门通过，才生成测试预测和SafeConf分数；测试扰动表达仍要在分数封存后一次性打开。

本实验修复的是上游预测器合同，不修改SafeConf公式，不把验证集改善写成外部测试成功。
