# E206：预测幅度与 SafeConf 融合的开发性分析计划

日期：2026-09-09

性质：**结局已打开后的方法开发，不是新的盲测或外部验证**

## 1. 为什么做

E201 的四背景正式评价显示：原始 SafeConf 风险分与真实错误同向，但预测幅度是更强的单一排序器。控制幅度后，SafeConf 仍保留正向关联。因此，本分析不再让两个信号互相竞争，而是检验一个更符合实际使用的方案：以预测幅度为主排序，再用 SafeConf 提供校正。

## 2. 数据纪律

- 输入固定为 E201 正式任务表中的 `primary_ge30` 全部 1,808 个任务；
- 不按照真实误差删除任务、细胞背景、扰动或模型；
- K562、RPE1、HepG2、Jurkat 四个背景全部保留；
- E201 真实误差已经在 2026-08-02 打开，因此本分析只能用于选择候选公式；
- 候选公式必须在新的外部数据打开答案以前再次冻结，外部数据才是最终确认集。

## 3. 候选公式

对同一目标细胞背景内的一批待复核任务，先分别把预测幅度和原始 SafeConf 转成百分位排序：

```text
R_magnitude = percentile_rank(predicted_magnitude)
R_safeconf  = percentile_rank(safeconf_e201_risk)

SafeConf-M(alpha) = alpha * R_magnitude
                  + (1 - alpha) * R_safeconf
```

其中 `alpha` 从 `{0.00, 0.05, ..., 1.00}` 中选择。`alpha=1` 等于只看预测幅度；`alpha=0` 等于只看原始 SafeConf。百分位排序只使用待排序任务的预测侧信息，不读取真实表达或真实误差。

2026-09-12 数值实现补充：`alpha` 网格均为二十分之一的整数倍。程序用对应整数比先
合并平均秩、最后统一除法，避免 `1-0.8` 等二进制浮点近似把理论并列分数错误拆开。
0.80/0.20 的数学公式、输入、数据和候选网格均不改变。截止分数仍并列时，E206 沿用
冻结的任务标识哈希给出可复现顺序。

## 4. 评价方案

### 4.1 描述性权重曲线

在四个背景分别计算后取宏平均，展示不同 `alpha` 下的：

- Spearman：风险排序与真实误差排序的一致性；
- 20% 复核效用：有限复核预算下，选中任务的错误富集程度；
- Top-20% 抓取率：预测高风险集合与真实最高错误集合的重叠比例。

这张曲线用于观察和选取候选权重，不作为独立验证。

### 4.2 留一背景开发验证

每次完整留出一个细胞背景。只在另外三个背景上选择使宏平均 Spearman 最高的 `alpha`，再把它用于被留出的背景。并列时选择更接近预测幅度基线的较大 `alpha`，减少额外校正。

四次留出均完成后，报告每个背景相对“只看预测幅度”的变化。该步骤避免直接在某个背景的真实误差上为该背景挑权重，但由于 E201 结局此前已经整体打开，仍应称为内部开发证据。

### 4.3 簇自助法

以扰动条件为簇进行 5,000 次自助重抽样，同一扰动在多个背景中的记录一起抽取。报告固定候选公式相对预测幅度的配对差值和 95% 区间。

## 5. 今晚允许形成的结论

可以说：

- 预测幅度应进入正式风险路由公式；
- E201 开发分析中，融合是否改善整体排序，以及改善在四个背景间是否一致；
- 由 E201 选择出的候选权重是多少。

不可以说：

- 新公式已经通过新的盲测；
- 新公式在任意数据、任意模型上都优于预测幅度；
- 已经保证期刊录用或已经节省湿实验。

## 6. 后续冻结门

E206 输出后，只允许选定一个最终公式。其代码、权重、输入字段、主指标和停止条件需要在 GitHub/Gitee 留痕，然后才可在一个新的数据家族或一个不同预测架构上一次性验证。
