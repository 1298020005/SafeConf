# SafeConf 新架构研究计划：供用户与网页版讨论

状态：设计讨论稿，未启动训练。目标保留为计算机方向二区/CCF-B规格的真实方法研究。用户允许适当增加实验时间，优先要求架构成立、比较公平、每项工作能增强论文证据。详细参数与本机核验见同目录 `PUBLICSET_EXECUTION_CONTRACT_REVIEW_20261002.md` 和 `PUBLICSET_LOCAL_FEASIBILITY_20261002.json`。

## 一、负责人建议采用的架构

```text
公共真实实验＋当前任务的生物元数据/已知对照
                    ↓
            Public构建器 B
       输出生物参照μ、分散度、支持信息
                    ↓
当前模型预测p ─→ 预测与参照的差异（包含幅度）
                    ↓
       简单风险规则 / Source风险学习器
               ↑ 旧模型合法错误训练
                    ↓
        C没有自身反馈时的风险判断
                    ↓
   C真实反馈 → Target-only / Public+Target /
              Shared+Target个性化比较
```

Public学习真实实验之间怎样迁移，不用模型错误训练。Source负责学习这些证据如何对应预测错误。Target负责模型自身反馈后的适配。Source直接HGB与Source residual是同一风险层的两种实现，第一轮不强制串联，也不同时增加gate。

幅度是输入与固定对照，也已包含在历史距离展开式中；不重复加一次。Public的μ是生物效应，σ是历史分散度，二者不是自动校准的“出错概率”。

## 二、为什么这轮优先改Public

已有HGB确实学习了逐条历史的迁移误差，且包含conflict和support_fraction。新模型要证明的是学习集合上下文的额外价值。

本机Source的1808任务中，K1=132、K2=423、K3=1253；McFaline开发生物验证542任务的K为7–14。已有数据足以检验小集合和较丰富集合，无需先凑新模型名字。GPU有两块24GB RTX6000；可复用Torch2.6的现有环境，默认Torch2.11环境不兼容驱动。

第一轮固定四臂：支持加权均值、当前HGB、逐条MLP、DeepSets。后两者输入、loss、参数宽度与预算一致；DeepSets仅多一个学习的集合上下文。内容仍以原始完整effect向量加权，不让PCA重建误差充当方法变化。

固定配置为PCA32、两层64宽token编码器、64宽评分头、masked mean、AdamW 0.001、权重衰减0.0001、batch32、100epoch上限、patience10、三个原登记种子；50:50学习/支持混合保持。所有PCA、标准化、选epoch都在合法训练分区完成。

## 三、第一批实验怎样安排

| 工作线 | 具体动作 | 需要回答的问题 |
|---|---|---|
| Public GPU线 | Source及McFaline合法生物开发集的四臂比较，先原fold0验证代码与耗时，再完整五折 | 整组处理是否比逐条处理更好；是否超过当前强简单参照 |
| Source CPU线 | 先建立教师checkpoint训练范围与query单元的对应表，再导出/复用合法source-validation错误 | 旧错误是否在没有看到评价答案的条件下帮助另一研究 |
| 统计与论文证据线 | 同任务比较、5000gene簇统计、信息预算、实际成本和主张矩阵 | 优势具体来自哪类信息，效应和不确定性是否足够 |

CPU线有真实修正：旧K562预测器训练时见过HepG2/Jurkat treated。直接把它的旧误差缓存用于“Replogle→Nadig”并不能自动构成干净留出。优先使用已排除相应query context的现有checkpoint及合法validation预测；缺向量才做一次有成本上限的旧模型推理。数据合同未闭合时不跑误导性比较，Public GPU线继续。按query context隔离后，原40次风险拟合可能需要最多80次；这是必要的数据范围拆分，不是新增网络。

## 四、采用或停止的方法规则

先看生物重建，再看风险排序。固定R_hist为主读出，direct RMSE为预登记辅助读出；同时报幅度与支持量规则。只改善生物重建，不足以采用为可靠性主方法；只改善辅助读出，则如实记录其依赖的读出条件，不能更换主指标宣布成功。

结构贡献看DeepSets−MLP；实用价值看DeepSets对当前HGB、支持均值及强简单规则。保留门沿用ΔU20≥0.005、≥60%有效分层非负、覆盖≥80%及原AURC/漏检安全限制，附置信区间。三个种子全部报告，不选最好一次。

- DeepSets稳定改善风险：冻结它，完成内容置乱与原HGB风险层的同条件验证。
- MLP与DeepSets接近且MLP达到同样实用门：优先采用简单MLP，贡献表述跟随证据。
- 两者都未提升：停止这一架构候选，保留现有Public，继续合法Source和反馈任务。必要时只做一次凸组合上界诊断，解释权重学习是否本来缺少空间。

当前最关键的完整结果是：同样的历史与预算，哪种构建器真正多识别出高误差任务，并且没有牺牲低风险任务的可靠性。

## 五、后续Source与Target怎样接上

Source数据资格通过且确有负迁移时，最多做一次等预算的直接HGB与锚定残差HGB比较。基础分、误差标签必须同尺度并真正交叉拟合；基础校准使用的Source错误计入总预算，残差允许负值。不能把一个原始RMSE分数和误差排名直接相加。

详细合同将基础校准固定为非负系数Ridge，避免无意翻转公共规则；CDF参照和内部验证基因分离，使基础分与残差使用同一个合法目标。匹配对照用相同记录、特征、标签和权重，原全预算HGB另作强对照。这是新DEV版本，旧确认不自动适用。

本轮不启动新的compatibility gate或GNN。它们仍缺少足够独立的启用收益数据，复杂化不能代替该证据。

Target保留四类反馈比较及PertEMA：Shared、Target-only、Public+Target、Shared+Target。参照/风险版本相同的结果复用，改变的组合在同一个反馈池和相同标签预算下重跑。后续C可成为新模型D的历史来源，但需真实held-out错误、版本和输出合同合格；同一评价数据不能同时选新方法又确认它。

## 六、职责、时间、资源与交付

我承担研究负责人职责：独立排队、检查数据资格、诊断故障、进行一次有依据的修复、停止低价值分支、选择有证据的模块并持续提交Git。结果不好时交付下一项具体动作和依据，不能把问题交回用户，也不能靠改指标、挑任务或换已见测试集获得阳性结果。

时间允许放松，但设限：先在24小时内交原型、耗时与Source资格结论；完整验证预计再需1–2天。原型累计4GPU-hours，后续完整验证另设12GPU-hours上限并受原96GPU-hours总账约束；缺失成本先对账。新阶段单独记录，不重启旧72小时计时。当前不新增大型上游训练、第二个集合网络或大规模运维功能。

交付四臂完整表、Source合格范围/结果、受影响的反馈对照、最多三张主图、每个模块的保留/拒绝决定、信息预算与复现入口。原合同交付物继续保留；论文正文当前暂缓。

请网页版重点反驳三件事：
1. 这套Public生物监督与risk读出是否对齐，四臂是否真正隔离了集合交互价值？
2. Source教师训练暴露和Source residual的尺度桥接是否还有隐含泄漏或不公平？
3. 在当前数据和时间内，这些比较能否形成超过强简单方法的实质贡献；若不能，下一项最值得的具体数据或模型投入是什么、需要多少成本？

本计划不将“所有模块采用”设为目标。采用有真实增量的组合，明确其适用范围，才是为投稿准备证据。
