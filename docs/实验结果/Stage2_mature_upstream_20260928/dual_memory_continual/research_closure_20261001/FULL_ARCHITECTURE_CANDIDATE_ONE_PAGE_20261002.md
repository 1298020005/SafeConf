# SafeConf 四层架构候选：一页设计与负责人判断

状态：供用户/网页版评审；尚未实现或启动新训练。它是独立开发候选，不继承旧方法确认资格。旧冻结结果、a243310收口计划的数据合同/预算继续保留。

**我赞成的信息结构：预测幅度 → 公共生物参照 → 源错误修正 → 目标个性化。当前最值得实现的增量是小型Public集合学习器；Source residual和兼容性gate应分阶段证明，GNN暂不开发。**

## 1. 幅度如何成为起点

Magnitude保留为输入和必报对照。它在Source有较强排序，在McFaline为负方向，不能注册成普适安全风险底座。对同轴预测p、历史均值μ和历史分散度σ²，已有强规则可展开为：

`R_history² = ||p||²/G + (||μ||²/G − 2 p·μ/G + σ²)`。

第一项就是幅度，Public交叉项允许增减风险；这使幅度与Public自然配合，而无需手定两个正风险分数的权重。该恒等式属于已有基线解释，不作为新理论贡献。无历史的预测分数仍需独立验证，不能由此宣布安全回退。

## 3. Public的最小结构候选

`任务生物元数据/预测前control + {合法历史token} → 小型DeepSets权重器 → μ、历史分散度、支持量/状态 → 固定风险规则`。

每个token包括训练区PCA压缩的历史effect、context/condition匹配、真实重复性Quality、Support和Conflict；cell/guide/plate数量属于Support。任务query先使用生物元数据/control，不使用当前truth或误差。μ由学习权重加权**原始同轴完整effect向量**生成，避免把低维解码误差混入参照。

内容与支持量分别输出；σ先采用可核对的历史分散度，不把它称为校准预测不确定性。缺Quality就标未知，不伪造质量监督。若以后用p查询注意力，仍可共享网络参数，但参照变为模型条件化输出，须另做消融，不能混称纯生物先验。

[Deep Sets](https://papers.nips.cc/paper_files/paper/2017/hash/f22e4747da1aa27e363d86d40ff442fe-Abstract.html)提供无序集合结构；[Set Transformer](https://proceedings.mlr.press/v97/lee19d.html)进一步建模集合内相互作用。当前先选DeepSets：低维token、mean聚合的集合上下文、逐条权重，隐藏宽度64、参数上限约10万；这些是拟议原型上限，不是性能承诺。

## 4. Source residual／Gate怎样定义才成立

Public首先学μ/分散度；**生物重建改善不保证风险排序改善**，已有Public重训实证支持这一警惕。风险base须明确从p与参照构造，并与最终误差目标同尺度；不能直接把原始RMSE代理与[0,1]残差相加。

拟议接口：`δ_source = z_error − b_OOF`；`risk = clip(b + γ δ_source + λ δ_target, 0,1)`。b和z的尺度桥接只能由允许的训练区确定；若b的校准用了Source错误，这些标签同样入账。两阶段重复使用相同Source标签不能宣称获得两份独立信息；必须对比同特征/同标签预算的直接HGB。

γ的监督来自交叉拟合后“启用残差比不启用减少多少损失”的gain/regret。任务级损失仅是训练代理，仍要通过U20/AURC/漏检率外层验证。Similarity只是输入，不能作为收益标签。当前跨研究负结果说明需要研究负迁移，尚未证明新gate会解决它。所有阶段按gene/生物任务整体划分，尺度桥接、残差、gate各自使用合法OOF。

## 5. 第一轮只实现哪一版

首先完成a243310规定的上游训练暴露/合法源错误核验。随后在DEV/SEEN统计独立K、context组成、支持量；若多数集合只有1–3条，优先判断相互作用是否有学习信号，不能以“原始集合很大”作为Transformer理由。

唯一初始原型为**Public DeepSets＋固定历史风险规则**，同时保留四个必要比较：支持加权均值、当前HGB检索、逐条MLP、带集合上下文DeepSets。后两者用同一生物训练目标和监督预算，隔离集合相互作用与换损失的影响；四者均用同一bank、eligibility、gene轴/掩码、划分和评价队列。

分别报OOF生物重建与固定风险规则的U20/Spearman/AURC，并保留Magnitude和支持量规则。开发保留门沿用ΔU20≥0.005、≥60%有效分层非负及原安全约束；区间很宽时不称稳定增益。最多一个固定网络配置、3个预定种子、4GPU-hours原型预算，先实测单fold耗时；不做架构搜索。通过后才讨论Source residual，再讨论gate，避免一次改三个模块而无法归因。

现有McFaline/Orion错误今后可作为新版本的DEV Source经验，但须先闭合输出合同和合法OOF；一旦用于设计/训练，它们不能确认该新版本。现有模型名字多不等于已有合格Source池。新的独立确认资产仍是需要解决的实际缺口。

本设计与a243310的相对特征方案同时评审，**实施只选一条首要候选**。本次交付为设计，不是批准更改原冻结结构；原型进入单独DEV范围后运行。预计实现与首轮约半天至一天，完整嵌套验证另预留一天；无合格新资产时不承诺同期完成独立确认。
