审阅基准：`f185e07ab5a77c61449cb9ecfb2738dca1cd914c`。本文件提出一轮有界的新开发比较，尚未在服务器执行。旧 Public、Source、Target 结果及确认身份保持不变。正文、PDF和投稿打包继续暂缓。

## 1. 负责人决定

第三部分允许使用 XGBoost，不要求和 Public/Source 使用同一算法。优先复用官方 PertEMA 的 XGBoost 配方作为反馈候选，配对比较现有 HGB 和一个仅针对小样本叶节点限制的 HGB 新配置。选型由训练侧证据决定，不能因采用了不同算法就声称独创或更好。

HGB 与 XGBoost 均为已有通用算法。研究对象是公共实验和跨模型信息如何帮助目标反馈学习，以及何时值得替换无反馈规则。自己的训练参数、实现与信息组织可以构成项目成果，算法名称不属于本项目原创。

执行代理继续承担研究与实验负责人职责：独立核对意见、维护比较公平性、处理工程故障、辨别失败原因、执行有依据的最小修复并给出采用决定。可提出有证据的异议，但无需把参数选择交回用户。完成一次提交或发现一个负结果后，继续下一项已获授权的工作。旧阶段完成不等于当前研究已经具备投稿结论。

## 2. 已核到的事实与本轮要回答的问题

当前 `feedback_alignment_v1/SEED_MEAN_METRICS.csv` 的同一212任务/152基因评价池中：

| 配置 | 10%反馈 U20 | 100%反馈 U20 |
|---|---:|---:|
| PublicTarget_HGB | 0.080694 | 0.756103 |
| PertEMA_Public_RawAligned（官方XGBoost工厂、任务适配） | 0.776493 | 0.753235 |
| SharedTarget_HGB | 0.080694 | 0.761680 |
| SameContext_R_history（无目标错误反馈） | 0.837668 | 0.837668 |

这批表明：XGBoost已经接入并跑过；此前六项预测输入的弱PertEMA代理不能代替加入合法生物背景的比较。现有数字为已见数据结果，不能用来挑新方法后再称独立确认。较高点估计也不自动等于可靠优势。

收口报告明确：10%预算有37条训练记录，HGB每叶最少20行，实际200棵树均只有根节点。这是该配置不能有效分裂的证据，不支持少量反馈本身没有价值。

本轮回答三件事：
1. 在相同输入与标签预算下，哪个反馈学习配方有效？
2. 同一学习器加入公共内容、再加入旧模型共享分数，分别增加多少？
3. 这些反馈学习结果能否增加强无反馈公共规则没有提供的价值？

不重复Public四臂、不重训上游、不再增加集合网络/gate/新残差。第一、二模块冻结，仅改第三模块的训练配方。

## 3. 先复用，再补齐固定比较

### 学习器

- **H0：原HGB。** 200轮、深度3、学习率0.05、每叶20行、L2=10，沿用已冻结其他参数及预处理。作为保留对照，不覆盖旧模型。
- **H1：小反馈HGB候选。** 只把每叶行数改成 `min(20, max(2, n_fit // 10))`。`n_fit`为当次实际拟合、有效且去除重复任务记录后的训练行数；内层拟合独立计算，不能读取验证/评价行数。其他参数不变。这个规则是一次预先指定的开发假设，不是理论最优值；不搜索5/10/20等网格。允许分裂仍不保证有效，常数特征、粗标签或正则化仍可能限制训练。
- **X0：PertEMA官方XGBoost配方的共同输入适配。** 固定官方提交 `43c09a32e23d0ee2ae5dfbab21b2deeab27f1803`，调用 `src/pertema/run_estimator.py::gbt`。300棵树、深度6、学习率0.05、subsample/colsample_bytree=0.8、hist。线程及种子继续用已登记适配规则；不得悄改其他参数。官方默认未显式列出的参数保存实际解析值与库版本。

H0/H1只相差一个训练规模规则，回答明确配置限制。X0与HGB的树容量和算法实现同时不同，其结果只支持固定配方比较，不能把全部差异归因于某个单独算法机制。

### 信息条件

每种学习器均使用三类已登记输入：

- **F0：P。** 原六项当前预测特征，包含幅度。
- **F1：P+Public。** 同一预测输入，增加相同对齐公共参照及原七项公共特征。
- **F2：P+Public+Shared。** F1再加同一个冻结且来源合格的共享风险分数。

本轮不在某一种学习器中单独增加新的质量、背景或模型ID。原公共特征不含的质量字段不偷偷补入。缺少合法Shared分数只将F2标记输入未就绪，F0/F1继续；不把不同Public版本的结果混表。

反馈预算仍为原固定嵌套基因簇的10/25/50/75/100%。0%只展示无需C错误训练的已登记公共规则与Shared；目标学习器标记未拟合。

先生成缓存复用表，逐项核对数据角色、任务ID、特征值、Public/Shared版本、CDF、样本权重、参数、随机性与输出。当前 X0/F0、X0/F1 很可能可复用；X0/F2是否为当前对齐版本需要实际核查。接口签名不同就重新训练并独立命名，不能仅凭名称复用。

原HGB为确定性且输入完全相同的配置只拟合一次。XGBoost沿用三个已登记种子；报告全部及平均，不选最好一次。不重复运行确定性配置增加所谓工作量。

## 4. PertEMA比较的边界

共同输入矩阵用于拆解信息与学习配方的贡献。六项P特征版只能称 `PertEMA common-input adapted`，不能代表完整官方PertEMA。

保留并核对已完成的native-control适配：它使用控制状态、基因表示、相似度等较完整信息；其中技术plate方差替代donor方差、表达尺度和错误目标的差异继续披露。若Public版本不同，旧native结果单列表，不与新表直接相减。

若本轮要对PertEMA方法本身作强弱结论，先完成同一任务与反馈预算、当前对齐Public版本下的native-control配对。已有精确相同结果复用；缺失项最多先补10%和100%两个登记端点，不按结果临时选择端点。

只比较raw风险排序时，所有方法使用同一风险方向和原评价流程；不宣称已复现isotonic或split-conformal。不得复制官方脚本中在评价集尝试两个方向再取最佳的 `best_aurc` 做法。排序、校准准确性和区间覆盖分别是不同能力。

## 5. 不用已见评价集选择新学习器

新配置的提出已受到旧结果启发，明确标记新DEV方案。现有212任务评价池保持SEEN性质。

- 在已有331任务/228基因反馈池内，以预先固定的基因分组做三折内部评价。每个预算只开放该预算允许的记录；不能用全部反馈选择10%配置。
- CDF、填补及其他有拟合步骤的处理只使用当次内层训练记录。样本权重继续原簇均权及总尺度，不能给XGBoost单独放大权重改变正则化和分裂条件。
- 验证查询的真实答案与不合法重复不能作为其他训练行的公共历史进入拟合。合法同扰动其他条件的历史继续保留，不能把它误删。
- 内部验证不够计算原宏U20或覆盖护栏时，写明不足，不借用永久评价池补足。可以完成诊断比较，暂不作发布选型。
- 在反馈训练侧形成候选及启用规则后，冻结参数、预算、全部评价预测和哈希，再统一计算212任务结果。包括失败预算，不能只报优胜预算。
- 不把每预算评价赢家拼成一个部署模型。任何分阶段使用不同学习器的策略都必须在训练侧预先确定；本轮默认保留同一配方跨预算曲线。

配对统计继续使用相同152基因的5000次抽样、相同任务集合和既有指标口径。不能把542任务开发表、543任务原主表与212任务反馈表混算。报告U20、Spearman、AURC、原固定覆盖率误差及漏检。U20仍是主要排序指标，不按有利指标更换主结果。

## 6. 必须产出的诊断与实际取舍

每个预算记录实际任务/基因数、权重和与有效样本量、CDF不同标签数、风险分数不同值数、原始/裁剪分数范围、有效树分裂数和运行时间。

- H1消除根节点退化且在训练侧改善：保留该小样本候选，继续完整曲线；只能称固定HGB配方修正。
- X0/F1表现较好：可以让XGBoost承担第三模块，不要求与前两模块同算法，也不宣称HGB仍独享或算法创新。
- 同一X0加入Public稳定改善：支持公共信息对目标风险学习的增量；须进一步对最强无反馈规则比较。
- F2没有超过F1：第三模块不强制接Shared。跨模型模块仍按自己已验证的冷启动范围保留。
- 两种学习器加反馈仍未超过公共规则：保留公共规则服务，记录候选拒绝；不宣布所有自学习均无用。结合分裂、学习曲线及误差模式说明本轮缺口属于表示、监督规模、学习配方或尚无法区分。
- 只有低风险误差等次指标改善而U20未改善：如实报告收益取舍，不能替换主要主张。

不强迫第三模块增加U20，也不因旧HGB失败就删掉整个反馈能力。方法失败最多一次写明原因与范围的修复；除H1这一已登记开发修改外，不继续搜索新的损失、混合比例或网络。

发布沿用已有开发验证与旧任务检查门，预算到达只触发训练。Public快照、预处理、Shared及目标学习器一起绑定版本；旧预测和失败候选保留。真正持续收益需后续未参与该次选择的任务支持，当前静态反馈曲线不能替代它。
