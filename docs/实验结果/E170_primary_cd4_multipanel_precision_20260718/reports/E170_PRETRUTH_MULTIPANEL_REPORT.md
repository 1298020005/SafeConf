G2 与 G3 全部通过，说明各模型确实产生了任务依赖预测，SafeConf 分数也不是常数。失败集中在 G4，表明问题是“相同模型族换 seed 后，目标风险次序在不同 200-target 面板上不稳定”，不是输入泄漏、预测器完全退化或分数无分辨率。all-200 比 seen-160 更容易通过，还说明 support=6/0 的 160/40 大分层会人为提高总体排名一致性，不能用总体 gate 掩盖 seen 目标内部的不稳定。

这一步没有真实 test error，不能判断 P01、P02、P04 上 SafeConf 与 magnitude 谁更好，也不能把 P03 单独解封后当成预注册四面板结果。下一阶段只能在 train/validation 或另一个开发数据上解决 seed 不稳定，再用剩余未读目标建立新的冻结确认；E170 的 800 个 test outcomes 继续保留未读。
