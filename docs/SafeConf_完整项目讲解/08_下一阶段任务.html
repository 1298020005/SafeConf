1. 全局路线

2. 路线 A：把当前 SafeConf 做成可交付系统

A1 冻结 claim matrix

Claim 是论文或汇报中的结论句。Claim matrix 是“结论—证据—限制”的对照表。

  • 每个结论对应唯一结果表或图。
  • McFarland 失败、Tahoe 抽样和 magnitude 更强必须保留。
  • 冻结公式、数据划分和评价口径，不再事后改规则。

A2 统一结果产物

同一个数字只能有一个正式来源；汇报图、论文表和说明文字都从它生成。

  • 统一数据集名称、任务数和小数位。
  • 图中标注 pair / cell-line / drug 的留出方式。
  • 给每张图补“它回答什么、不能回答什么”。

A3 建立复现入口

复现 指别人按说明运行后能得到相同结论；脚本、输入和环境缺一不可。

  • 一条命令运行 smoke，小数据先检查流程。
  • 一条命令运行 formal，生成正式 CSV 与图。
  • 保存环境、随机种子、输入清单和日志。

A4 写清系统边界

SafeConf 当前给每个任务一个共同风险值。某个模型在该任务上的专属置信度尚未进入当前协议。

  • 适用：高风险任务排序、复核和湿实验分诊。
  • 不适用：声称能为任意模型给出校准概率。
  • 尚未完成：同一任务上自动选择最佳模型。

3. 路线 B：从“任务难不难”走向“哪个模型更可靠”

先决条件：必须拿到同一任务上多个模型的逐基因预测向量，以及同一真实效应向量。只有汇总分数或论文表格，不能完成模型级验证。

模型级记录应长什么样

dataset, task_id, model_id, split,
context_similarity, support_count,
cross_model_disagreement, native_uncertainty,
true_error, predicted_risk

Cui, task_001, GEARS, test, ...
Cui, task_001, CPA,   test, ...
Cui, task_001, scGPT, test, ...

这里的 model_id 是关键：没有它，系统仍然只是在给“任务”打分。

Task-only

只用背景相似度、支持数等任务特征。回答“这个任务普遍难不难”。

Model-only

只用模型自身的不确定性、重构误差或集成方差。回答“这个模型自己是否犹豫”。

Combined

把任务特征与模型证据合并。只有它稳定优于前两者，扩展才有实质价值。

新指标为什么需要

指标 要回答的问题 理想结果
Partial Spearman ρ 控制 magnitude 后，风险排序还和真实误差一致吗 跨数据集为正，置信区间稳定
AURC 拒绝高风险预测后，保留部分的误差是否下降 低于随机或基线
Calibration 预测“风险 0.7”的样本是否真的更常出错 预测风险与实际频率接近
Top-k enrichment 人工只复核最危险的 10%，能多抓到多少错误 显著高于 1×
Model-selection regret 系统选的模型，比事后最优模型多错多少 越接近 0 越好

4. 明确停止线：这些事现在不要做

不要继续扩 Tahoe shard
现有 D1、D2、D4 已稳定为正；更多相似抽样不会自动解决 held-out drug 或模型级问题。
不要在测试集调组合权重
用最终结果挑最好权重会产生数据泄漏。权重必须预先固定或只在训练折学习。
不要把 cell-line 外推写成 drug 外推
两者是不同问题。没有足够药物支持，就应直接标为不可评估。
不要修改 frozen v0.2 追数字
冻结协议的价值就是规则先于结果。新公式应另起版本并独立验证。
