实验证据谱系：742 个文件怎样读

实验目录保存 39 个顶层结果包，共 742 个文件。这里按问题、时间和证据级别整理，避免把 smoke、旧版和正式结果混用。

1. 文件类型各自承担什么

CSV 表

保存逐记录、逐折或汇总数字，是核对结果的主要数据源。

Markdown 报告

记录问题、结论、限制和文件入口。报告需要回查 CSV。

JSON 状态

保存参数、种子、运行状态、审计摘要和机器可读元数据。

PNG / SVG

论文或汇报图。SVG 是矢量图，放大后文字和线条仍清晰。

2. 证据级别

词含义
Smoke冒烟测试；用极小数据检查文件、代码和输出链路。
Probe探测实验；规模大于 smoke，用于判断方向，尚未达到正式结论标准。
Corrected发现空白行、输入或实现问题后重跑的修正版。修正版取代相应旧表。
Superseded旧结果已被更严格版本取代，保留文件只用于追溯。
Preregistered实验问题、输入、指标和通过门槛在运行前写定。
Canonical / source of truth同一结论存在多个版本时，指定的权威来源。

8. Task-risk、LODO、LOPO 和 E8b

Task-risk 动机

V0 与 ContextSim 的误差 Spearman 为 0.973；task identity 解释 93.6% 误差方差。结论只覆盖这组参考预测器。

LODO

Leave-One-Dataset-Out：留出整个数据集训练风险模型，检验跨数据集迁移。

LOPO

Leave-One-Predictor-Out：留出一种预测器，检验风险规律能否迁移到未参与训练的预测器。

E8b

Frangieh 74 个 perturbation、15 种方法；median ρ=0.584，14/15 为正。输入是公开 benchmark 聚合误差，证据级别为外部关联。

E8b 样本量边界：Nstimulated 基线 median ρ=0.764，高于 frozen risk。控制 log(Nstimulated) 后 median partial ρ=0.335，属于事后诊断，不能写成预注册 gate。

10. E9–E32 投稿升级与外部验证

E9 强基线审计

把 SafeConf 放到 magnitude、sample-size 等强基线旁边看。作用是防止结论写过头。

E10 外部探针

先查数据资产，再跑 KaggleCrossCell、Haber、Parekh。当前定位是外部验证侦察，不是最终外部验证。

E11 selective prediction

从“丢掉高风险预测后平均误差是否下降”来审计实际分诊价值。它提供应用角度，但不是严格覆盖保证。

E12 外部面板

把候选扩到 6 个数据集，筛出 sciplex3、KaggleCrossPatient、crossPatient 三个可按 held-out pair 评价的外部对象。

E13 官方 sciplex3

把 A549、K562、MCF7 三个官方文件合成为三细胞系 drug-dose 面板，给 chemical 外部验证一个更干净的任务定义。

E14 full-743 gene1000

保留全部 743 个共享 drug-dose，把外部 chemical 面板扩大到 2,229 tasks；当前为 1,000-gene 快速验证。

E15 full-743 gene2000

把同一面板提高到 2,000 genes，检查 E14 信号是否随基因数增加保持稳定。

E16 full-743 gene3000

继续提高到 3,000 genes，验证 full-743 chemical 信号的连续性。

E17 full-743 gene5000

完成 5,000-gene full-743 正式版，把 E14–E16 的 sensitivity 升级为 formal evidence。

E18 model-vector audit

检查 GEARS、scGPT、CPA 是否已有可进入 SafeConf 协议的逐任务 predicted/true vector。

E19 GEARS-only supplement

整理 GEARS-only 既有 formal/probe 结果，作为补充证据，边界单独标明。

E20 adapter contract

检查旧 sciplex3/GEARS 输出能否 strict pass；结果显示可审计但还不能直接做统一多模型验证。

E21 strict remediation

把 E17 抽样包改成 task-scoped true effect，证明 strict 合同修法可行。

E22 generator smoke

新跑 Haber 200-gene smoke，证明修改后的生成器输出直接 strict pass。

E23 shared benchmark

固定 120 个 task groups 的 manifest，要求后续模型 adapter 对同一任务输出预测向量。

E24 compatibility audit

纠正 E23 不能直接给 GEARS 的问题，并把路线转向 gene-perturbation GEARS strict 证据包。

E25 GEARS strict records

把 Adamson/Dixit/Norman 的真实 GEARS formal 输出补齐 strict provenance，形成 54 条可校验证据。

E26 GEARS single-model

在 E25 strict 包上评估 GEARS-only 风险线索；预测效应幅度可排序高错误，原生 uncertainty 不可用。

E27 scGPT forward smoke

修正 scGPT 源码路径问题，用 whole-human checkpoint 生成 strict-pass scGPT smoke 记录。

E28 GEARS–scGPT shared

Adamson 上 3 个任务、两个 predictor、512-gene panel，共用 task-scoped true effect。

E29 GEARS–scGPT risk

把 Adamson shared 任务扩展到 7 个，计算双模型 disagreement 与真实误差的任务级关系。

E30 GEARS seed overlap

审计现有 GEARS 三个 formal runs 的任务重叠，确认不能直接声称 seed-ensemble uncertainty。

E31 GEARS fixed-test

给 GEARS exporter 增加固定 test perturbation 清单，验证后续三 seed 重跑可以测同一批任务。

E32 GEARS 3-seed

在固定 Adamson 7-task panel 上跑通 3 个 seed，并计算 seed disagreement 与误差的初步关系。

E10–E32 边界：E10 overall 最强为 model_disagreement_risk，aligned Spearman = 0.559；E14/E15/E16/E17 full-743 的 learned ρ 分别为 0.862、0.899、0.903、0.891；E18 说明 GEARS 有 54 条可读向量，但 scGPT/CPA 暂无 SafeConf PredictionRecord；E19 只提供 GEARS-only supplement；E20 显示现有 10 个 bundle 都可审计但 0 个 strict pass；E21/E22 只证明 task-scoped true effect 修法和生成器合同修复可行；E23 固定 shared manifest；E24 纠正模型家族兼容性；E25 让真实 GEARS formal 输出 strict-pass；E26 完成 GEARS-only 单模型风险审计；E27 让 scGPT 进入 strict smoke；E28 证明 GEARS–scGPT 双模型合同对齐可行；E29 在 7 个 Adamson shared tasks 上完成小样本风险审计，但 disagreement 只有弱正相关；E30 说明现有 GEARS runs 任务重叠太少，不能直接写 seed uncertainty；E31 已打通 GEARS fixed-test exporter；E32 已跑通 fixed-test 3-seed smoke，并出现 seed-disagreement 初步正信号。下一轮重点是提高到正式 epochs、扩大共享任务数、固定 split 或 CPA adapter，而不是把 smoke 写成正式 benchmark。
