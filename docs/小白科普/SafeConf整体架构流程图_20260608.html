SafeConf 小白架构流程图

从 0 开始理解：这个项目不是造一个新的预测模型，而是给已有 single-cell perturbation prediction（单细胞扰动预测） 的结果做 confidence scoring（可信度打分） 和 quality control（质检）。

0. 先给你一句人话

别人做的是“预测细胞会怎么变”。SafeConf 做的是“这个预测结果能不能信”。

厨师 predictor（预测器），比如 V0 / ContextSim / 以后可能接 GEARS。
菜品 predicted effect（预测效应），也就是模型预测扰动后基因表达怎么变。
质检局 SafeConf。它不做菜，只判断“这道菜靠不靠谱，能不能端上桌”。
你最容易混淆的点：SafeConf 不是 GEARS（图神经网络扰动预测模型） 这种“厨师”。SafeConf 是第三方质检系统。

1. 总览图：谁做预测，谁做质检，谁看答案

这张图的核心：预测和质检是分开的。预测器先给答案，SafeConf 再给这条答案打可信度分。

2. 数据怎么流动：从 h5ad 到一行 PredictionRecord

英文词小白解释代码/文件位置
h5ad（单细胞数据文件）原始实验数据，里面有很多细胞和基因表达矩阵。数据集文件，不是代码。
context（背景）细胞类型、细胞系、疾病状态等。外卖比喻里就是“分店”。context 列
perturbation（扰动）敲一个基因、加一个药、加一个刺激物。外卖比喻里就是“菜品”。perturbation 列
true_effect（真实效应）真实实验里扰动后和对照组相比，5000 个基因分别变化多少。true_effects.npz
PredictionRecord（预测记录）一行记录一次预测：哪个数据集、哪个背景、哪个扰动、哪个预测器、误差是多少。PREDICTION_RECORDS.csv

3. 两个“厨师”：V0 和 ContextSim 到底怎么猜

V0StrongBaseline（强基线）

大白话：同一道菜以前平均做成什么味道，我就猜这次也差不多。

具体：主要用同一个 perturbation（扰动） 在训练集里的平均 effect（效应）。

代码：03_code/transport_models.py

ContextSimBaseline（背景相似）

大白话：找和当前分店最像的历史分店，参考它做同一道菜的效果。

具体：用 control_mean（对照组平均表达） 计算背景相似度。

代码：03_code/transport_models.py

这两个不是很复杂的深度模型。它们更像强基线：简单，但是不能小看。SafeConf 先在它们身上证明“质检分数是否有用”。

4. SafeConf 怎么打分：三条主线索

frozen v0.2（冻结协议） 主角。公式提前定好，不为 McFarland 等后验结果改公式。
learned calibration（学习型校准） 配角。它可以更强，但只能作为可选增强层，不能抢主方法位置。

5. 为什么 effect magnitude 是大问题

effect magnitude（效应大小） 就是“这次扰动本身改变得有多猛”。 如果一个扰动本来就让基因大幅变化，它通常更难预测，误差也更大。

这个点应该成为正文重点：SafeConf 的价值不只是“分数和误差相关”，而是“在效应大小这个强混杂因素存在时，仍然能做更诚实的可靠性评估”。

6. 当前证据怎么读：7 个主表数据集

数据集类型raw ρpartial ρ结论
CuiHacohen2023（免疫基因扰动）基因线0.4450.328正信号，旗舰数据集之一
Frangieh（黑色素瘤基因扰动）基因线0.5830.474很强，但 context similarity 有害现象要诚实讨论

McFarland（癌细胞药物）化学线-0.086-0.061失败边界，不能隐藏

最诚实的论文结论：基因线稳定，化学线有正信号但存在明确边界。不要写成“所有扰动类型都稳”。

8. 哪些是主线，哪些只是补充

主线 external reliability assessment（外部可靠性评估）/ QC protocol（质检协议）。
主方法 frozen v0.2（冻结协议）：简单、可解释、提前固定。
可选增强 learned calibration（学习型校准）：更强，但不能抢主角。
压力测试 LODO（留一数据集组外部验证）：只能写成 stress test（压力测试）。
失败边界 McFarland：v0.2 失败，但这正好说明协议诚实。
外部储备 Tahoe：sampled validation（抽样验证），不是主表。

9. 你现在该怎么学

  1. 1先看 数据到底长什么样，把 h5ad、矩阵、向量、PredictionRecord 先看实。
  2. 2再看这份架构图，只记住“预测器做预测，SafeConf 做质检”。
  3. 3如果某个字段看不懂，再查 真实数据实物拆解。
  4. 4最后才看代码，按第 7 节的顺序看，不要从一堆 CLI 脚本开始。
最后提醒：你不用现在就懂所有生物学。你先懂“数据怎么变成一行预测记录”“这行记录怎么被打分”“这个分数怎么被验证”，项目主线就通了。
