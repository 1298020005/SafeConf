# SafeConf 全流程拆解——从创造者到使用者

本文站在两个角度讲 SafeConf：
- **角度 A：你（创造者）是怎么造出 SafeConf 的**
- **角度 B：另一个研究者（使用者）怎么用你造的 SafeConf**

## 图 0：h5ad 文件里到底有什么？使用者需要真值吗？

```
h5ad 文件 = 单细胞实验的原始数据格式
┌──────────────────────────────────────────────────────────────┐
│  obs（细胞表）：                                              │
│  ┌────────────┬───────────┬─────────────┬──────────────┐     │
│  │ cell_id    │ context   │ perturbation│ is_control   │     │
│  ├────────────┼───────────┼─────────────┼──────────────┤     │
│  │ cell_001   │ A375      │ BRAF        │ False        │     │
│  │ cell_002   │ A375      │ BRAF        │ False        │     │
│  │ cell_003   │ A375      │ control     │ True         │     │
│  │ ...        │ ...       │ ...         │ ...          │     │
│  └────────────┴───────────┴─────────────┴──────────────┘     │
│                                                              │
│  X（表达矩阵）：每个细胞 × 每个基因的表达量                     │
│                                                              │
│  ⚠️ h5ad 本身已经包含了"扰动结果"                            │
│     因为细胞确实被扰动了，表达量是真实测出来的                  │
└──────────────────────────────────────────────────────────────┘

使用者用 SafeConf 时需要什么：
┌────────────────────┬──────────────┬────────────────────────────┐
│ 文件               │ 需要吗？     │ 说明                        │
├────────────────────┼──────────────┼────────────────────────────┤
│ h5ad（原始数据）   │ 必须         │ 用来算 control 和 true_eff  │
│ control_means.npz  │ 必须         │ 算 context_similarity       │
│ predicted_effects  │ 必须         │ 预测器的输出                │
│ true_effects.npz   │ 训练集必须   │ 算 historical_residual 等   │
│                    │ 测试集不需要 │ 打分时不需要测试集真值      │
└────────────────────┴──────────────┴────────────────────────────┘

简单说：
  • 使用者打分时 → 不需要测试集的真实答案
  • 使用者验证 SafeConf 是否有效时 → 才需要测试集的真实答案
  • true_effect 是从 h5ad 里算出来的（扰动组平均 - 对照组平均）
```

### 先把“真实值”讲成人话

```
真实值不是人工写的标签。
真实值 = 从实验测出来的表达矩阵里算出来的。

┌──────────────┐
│ control 细胞 │  没敲基因 / 没加药，代表正常状态
└──────┬───────┘
       │ 求平均表达
       ▼
 control 平均表达

┌──────────────────┐
│ perturbation 细胞 │  敲了基因 / 加了药，代表被扰动之后
└────────┬─────────┘
         │ 求平均表达
         ▼
 扰动组平均表达

true_effect = 扰动组平均表达 - control 平均表达
```

小例子：

```
control 平均表达       = [10,  8,  3,  6]
扰动后平均表达         = [13,  7,  4, 10]
true_effect           = [ 3, -1,  1,  4]

意思：
这个扰动让第1个基因升了3，
第2个基因降了1，
第3个基因升了1，
第4个基因升了4。
```

对应关系：

| 词 | 人话 |
|---|---|
| true_effect | 实验真实看到的扰动效果 |
| predicted_effect | 模型猜的扰动效果 |
| true_error_rmse | 模型猜的效果和真实效果差多远 |

补充：magnitude 是什么？

```
magnitude = predicted_effect 这一串变化整体有多大

predicted_effect = [0.2, -0.1, 0.0, 1.3]
magnitude        = 这串数字的整体长度

人话：
模型觉得这个扰动会把细胞搅动得多厉害。

为什么审稿人会盯这个？
因为“动静越大”的预测通常越容易错。
审稿人会问：
你 SafeConf 说它高风险，是不是只是因为它动静大？
```

## 图 C：一条数据从出生到打分的完整旅程

```
以 Frangieh 数据集、fold 0、任务 M229 × MAP2K1 为例：

1. 实验者在实验室做了真正的单细胞实验
   → 得到了 M229 细胞系 + MAP2K1 基因敲除后的表达数据
   → 写入 h5ad 文件

2. 你（创造者）下载了这个 h5ad
   → 算出 true_effect = 扰动组平均 - 对照组平均
   → 存入 true_effects.npz
   → 算出 M229 的 control 向量
   → 存入 target_control_means.npz

3. 数据切分：这条任务被分到 fold 0 的 test 集
   → true_effect 被锁起来，预测器看不到

4. V0StrongBaseline 来预测：
   → 在训练集里找所有 MAP2K1 扰动，算平均 effect
   → 这个平均值就是它对 M229 × MAP2K1 的 predicted_effect
   → 存入 predicted_effects.npz

5. ContextSimBaseline 来预测：
   → 在训练集里找和 M229 相似的 context
   → 用相似度加权平均它们的 MAP2K1 effect 当预测
   → 也存入 predicted_effects.npz

6. SafeConf 提取特征：
   → context_similarity：M229 和训练集里最像的 context 有多像？→ 0.72
   → support_count：MAP2K1 在训练集有几个背景研究过？→ 3
   → model_disagreement：V0 和 ContextSim 的预测差多少？→ RMSE = 0.08
   → historical_residual：MAP2K1 在训练集的其他背景上出错多吗？→ 0.05

7. SafeConf 打分（注意：用的是中位数和 IQR，不是均值和标准差）：
   z = (当前值 - 训练集中位数) / 训练集IQR
   → z_ctx = (0.72 - 0.60) / 0.25 = +0.48
     （中位数 0.60，IQR 0.25，比训练集一半以上都更像 → 好信号）
   → z_support = (log(4) - 1.0) / 0.5 = +0.77
   → z_disagreement = (0.08 - 0.05) / 0.03 = +1.0
   → 分数 = 0.48 + 0.77 - 1.0 = +0.25（中等偏上）
   
   ⚠️ 为什么用 median/IQR 而不是 mean/std？
      → 对异常值更鲁棒（不会被极端值拉偏）

8. 验证（创造者做，使用者不需要）：
   → 打开测试集的 true_effect
   → 算 true_error_rmse = 0.089
   → 看 SafeConf 分数 +0.25 和真实误差 0.089 是否匹配
   → 在 100 条预测里做排序相关 → rho = 0.45 → 有效
```

## 图 F：预测器数量不同时的影响

```
情况 1：只有 1 个预测器
━━━━━━━━━━━━━━━━━━━━━
输入：1 个 predicted_effect 向量
可算特征：context_similarity ✅  support_count ✅  historical_residual ✅
          prediction_l2_norm ✅  prediction_magnitude ✅
算不了：model_disagreement ❌（没有第二个预测器可以比较）

⚠️ 当前 frozen v0.2 明确要求 2 个预测器
   → 代码里有 _validate_disagreement_predictor_sets_or_raise()
   → 单预测器的 fallback 公式目前不存在
   → 如果真的只有 1 个预测器，能不能用 SafeConf 是未解决的问题


情况 2：有 2 个预测器（当前默认）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
输入：2 个 predicted_effect 向量
可算特征：上面那些 ✅ + model_disagreement ✅

→ 公式完整版：分数 = z_ctx + z_support - z_disagreement
→ 当前 7 个数据集都是这个配置


情况 3：有 3 个或更多预测器
━━━━━━━━━━━━━━━━━━━━━━━━━
输入：N 个 predicted_effect 向量
可算特征：所有 ✅ + 多对分歧（C(N,2) 对）

→ 分歧信息更丰富，排序可能更准
→ compute_disagreement_batch.py 会自动处理所有配对
```
