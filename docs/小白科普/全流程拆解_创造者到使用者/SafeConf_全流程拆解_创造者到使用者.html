🗺️ 图 0 — h5ad 文件里到底有什么？

在开始之前，先搞清楚数据长什么样。SafeConf 的一切都从 h5ad 文件开始——这是单细胞实验数据的标准格式。

📦 一个 h5ad 文件 = 一次单细胞实验的全部数据

组成部分内容大白话
obs（细胞表）cell_id, context, perturbation, is_control登记簿：每个细胞来自哪个背景、被施加了什么扰动
var（基因表）gene_name, gene_id菜单：有哪些基因被测量了
X（表达矩阵）细胞 x 基因 的数值矩阵成绩单：每个细胞每个基因被测到多少
💡
h5ad 本身已经包含了扰动后的测量结果——细胞确实被扰动过，表达矩阵里的数字是实验室真实测出来的。true_effect 不是额外手写标签，而是从这些数字里算出来的：扰动组平均表达 - 对照组平均表达。

"基因表达"到底是什么意思？

这是理解整个 SafeConf 的基础。先用一个比喻：

🧬 基因 = 菜谱，表达 = 读菜谱

📖 基因（DNA 片段）
就像一本菜谱，写着怎么造某种蛋白质。
人体有约 2 万个基因 = 2 万份菜谱。
📝 表达（转录 mRNA）
细胞去"读"这份菜谱，抄出一份纸条（mRNA）。
读得越多 = 表达量越高 = 这个基因越"活跃"。
🍳 蛋白质（最终成品）
照着纸条做菜（翻译蛋白质）。
表达量高 → 菜做得多 → 细胞里这种蛋白质多。
💡
关键一句："基因表达"就是"这个基因正在被细胞读了多少次"。表达量高 = 读得频繁 = 这个基因很活跃。单细胞测序就是在数每个基因被读了多少条 mRNA。

单细胞测序测出来的数据长什么样？

就是一张大表格——每个细胞 × 每个基因 的 mRNA 数量：

BRAF 基因MAP2K1 基因GAPDH 基因... 基因 5000
细胞 112345...
细胞 28538...
细胞 315252...

每个格子 = 这个细胞里这个基因的 mRNA 被检测到多少条。这就是"表达量"。

"表达量"和"扰动效果"的区别

先别把这两个概念混在一起。它们不是同一个东西。

词人话解释例子
表达量 某个细胞里，某个基因被测到的活跃程度。可以先理解成“这个基因在这个细胞里有多亮”。 第 7 个细胞里，MAPK1 这个基因的表达量 = 8.2
平均表达 一组细胞在某个基因上的表达量取平均。 84 个加药细胞的 MAPK1 平均表达 = 10.5
扰动效果 effect 扰动组平均表达减去对照组平均表达。它表示“扰动以后变了多少”。 10.5 - 8.0 = 2.5
表达量：一个细胞 × 一个基因 的原始测量值
平均表达：一组细胞在一个基因上的平均值
effect：扰动组平均表达 - 对照组平均表达
🧠
最关键一句：表达量是实验测出来的“基因有多活跃”；true_effect 是后来算出来的“扰动让表达量改变了多少”。

扰动是什么？完整实验流程

扰动就是"故意搞一下细胞"，然后看基因表达怎么变。完整流程：

① 养细胞
一批细胞正常养（对照组）
一批细胞做扰动（扰动组）
② 做扰动
敲除一个基因 / 加一种药
对照组不动
③ 单细胞测序
每个细胞每个基因的 mRNA 数
④ 算变化
扰动组平均 - 对照组平均
= true_effect
为什么看变化而不是绝对值？

就像你想知道"下雨对路面的影响"，不是量"路面现在多湿"，而是比较"下雨前 vs 下雨后湿了多少"。扰动效果 = 变化量。

先把"真实值"讲成人话

真实值不是人工写的标签。它是从实验测出来的表达矩阵里算出来的。

1. 先有一批对照组（control）细胞
这些细胞没有被施加目标扰动，比如没有敲掉目标基因、没有加目标药。它们代表“没被动过时是什么样”。
2. 再有一批扰动组（perturbation）细胞
这些细胞被施加了目标扰动，比如敲掉一个基因，或加了一个药。它们代表“动过之后是什么样”。
3. 两边相减
扰动组平均表达 - 对照组（control）平均表达 = 真实扰动效果，也就是 true_effect。
对照组（control）平均表达 = [10, 8, 3, 6]
扰动组（perturbation）平均表达 = [13, 7, 4, 10]
true_effect = 扰动组 - 对照组 = [ 3, -1, 1, 4]

负数的扰动效果代表什么？

上面 true_effect 里的 -1 不是"出错了"，它有明确含义：

正数 = 上调
扰动后，这个基因表达变多了。
例：对照组 8 → 扰动组 11 → effect = +3
人话：这个基因被"激活"了。
负数 = 下调
扰动后，这个基因表达变少了。
例：对照组 8 → 扰动组 7 → effect = -1
人话：这个基因被"抑制"了。
接近 0 = 没变化
扰动对这个基因基本没影响。
例：对照组 3 → 扰动组 4 → effect = +1
人话：几乎没动。
🧠
关键理解：每个数字对应一个基因。一条 true_effect 向量（5000 维）= 5000 个基因各自的变化量。有的上调（正），有的下调（负），有的没动（接近 0）。不是所有基因都朝一个方向变。就像下雨天，有的地方积水多，有的地方几乎没湿。
📊
负数的意义不是绝对的：-1 和 +1 不代表"好"或"坏"，只是表达变化的方向。真正重要的是整条向量的模式——SafeConf 关心的是"预测器猜的那条向量和真实的像不像"。
🔢
上面为了好懂只写了 4 个基因。真实实验里常用 top 5000 genes（前 5000 个基因），所以 true_effect 通常是一条5000 维向量：一条向量里有 5000 个数字，每个数字对应一个基因的变化。不是"5000 个向量"。
词人话解释在 SafeConf 里叫什么
真实扰动影响实验里真的观察到的变化true_effect
模型猜的扰动影响预测器提前猜“扰动后会变成什么样”predicted_effect
猜错多少模型猜的变化和真实变化差多远true_error_rmse

true_error_rmse 到底是干什么用的？

你问了一个好问题：true_error_rmse 的意义是什么？是用来微调系统？还是预演？还是判断能不能做测试？

❌ 不是用来微调系统的
SafeConf 的打分公式（frozen v0.2）在看到 true_error_rmse 之前就锁死了。不会用它来调整参数。
❌ 不是预演
它不是"模拟测试"。它就是最终答案——预测器和真实值的差距。
✅ 是"判卷老师的红笔"
用来验证 SafeConf 打分准不准。SafeConf 说"这条预测风险高"→ 打开答案看 true_error_rmse → 真的很高吗？
predicted_effect = [0.2, -0.1, 0.0, 1.3, ...] ← 预测器猜的
true_effect = [0.3, -0.2, 0.1, 0.9, ...] ← 实验真的测到的

true_error_rmse = 两个向量的"距离"
= √( (0.2-0.3)² + (-0.1+0.2)² + ... ) / 5000
= 0.05（越小 = 预测器猜得越准）

🎯 时间线总结：true_error_rmse 在哪个阶段出现？

① 预测器出答案
predicted_effect 生成了
② SafeConf 打分
只看特征，不看答案
③ 打开答案
算 true_error_rmse
④ 对比
分数高的误差小吗？

只有创造者（你）做第 ③④ 步，用来证明 SafeConf 有效。使用者只用到第 ①② 步。

🧠
一句话：扰动就是“故意动一下细胞”，比如敲掉一个基因或加一个药；true_effect 就是“动完以后，细胞真实发生了什么变化”。

使用者打分时需要什么文件？

材料需要吗？说明
使用者自己的历史参考数据 需要 可以是 h5ad，也可以是已经提炼好的 effect/control 表。关键是训练历史里要能得到真实扰动效果。
control_means.npz 或等价 control 表 需要 保存对照组（control）平均表达，用来算 context_similarity 特征。
predicted_effects.npz 或等价预测表 需要 使用者自己的预测器输出。SafeConf 要给这些预测打分。
true_effects.npz（历史训练部分） 需要 用于计算 historical_residual、effect stability 等历史线索。
目标测试任务的 true_effect 打分不需要 只有验证 SafeConf 是否有效时才需要。真实使用时，正是因为还没做实验，所以不知道答案。
✅
一句话：使用者给预测打分时，不需要知道目标测试任务的真实答案。但 SafeConf 需要一部分历史真实扰动数据当"参考题库"。只有你要证明"SafeConf 打得准不准"时，才打开测试集真值做评估。

🔧 角度 A — 创造者的 7 步流水线

这就是你做 SafeConf 的全过程。从下载数据到验证有效，一共 7 步。

1

📥 收集数据

从公开论文 / 数据库下载 h5ad 文件。当前用了 7 个数据集：

输入：无（从公开数据库下载）
处理：收集多个数据集，覆盖基因敲除和药物扰动两种类型
输出：7 个 h5ad 文件 → 给第②步做预处理
数据集扰动类型特色
Frangieh 2021基因敲除黑色素瘤 + 免疫细胞共培养
CuiHacohen 2023基因敲除大规模 CRISPR 筛选
LaraAstiaso 2023 (ex vivo)基因敲除体外实验子集
LaraAstiaso 2023 (in vivo)基因敲除体内实验子集
SantinhaPlatt 2023基因敲除弱正信号（效果量小）
McFarland 2020药物扰动已知的 frozen v0.2 失败边界
Srivatsan 2020药物扰动sci-Plex3，大规模化学扰动
⬇️
2

✂️ 数据预处理 + 切分

输入：7 个 h5ad 文件（第①步产出）
处理：算 true_effect、control 向量、切成 5-fold 交叉验证
输出：true_effects.npz + control_means.npz + 任务表 → 给第③④步用

对每个数据集做三件事：

① 算 true_effect 向量：扰动组平均表达 - 对照组（control）平均表达（一条 5000 维向量，对应 top 5000 基因）

② 算对照组（control）向量：每个 context 的对照组细胞平均表达

③ 切成 5-fold 交叉验证

train/test 不是两种实验，是同一个数据里切出来的两份

可以把它想成一本已经有答案的题库。为了考试公平，我们故意把一部分答案先盖住。

同一个 h5ad
里面有很多 context × perturbation 任务。因为这是已经做完的实验，所以每个任务都能算 true_effect。
训练集 train = 可看的参考题
允许看 true_effect。用它当历史资料，算支持次数、相似背景、历史残差等线索。
测试集 test = 先盖住答案的考题
打分时不许看 true_effect。最后评估时才打开答案，看 SafeConf 排序准不准。
问题人话答案
训练集需要有真实扰动影响吗？ 需要。训练集就是历史上已经做过实验、能算出 true_effect 的那部分任务。
测试集打分时需要真实扰动影响吗？ 不需要。测试集真实答案先锁起来，SafeConf 只能用训练集统计量和预测器输出打分。
那测试集真实答案什么时候用？ 只在最后验证时用：打开答案，检查 SafeConf 有没有把高风险预测排到前面。
使用者为什么要提供 h5ad？ 为了提供历史参考题库和当前 context 的对照组表达。没有任何真实扰动历史，SafeConf 的很多线索就算不出来。
⚠️
Held-out pair 约束（极其关键）：
测试集里的 (context, perturbation) 组合 在训练集里不会出现。
但 context 和 perturbation 各自在训练集别处都见过。
→ 测试的是"新组合"，不是"完全未见的细胞系或扰动"。

产出文件：

  • true_effects.npz — 真实 effect 向量
  • target_control_means.npz — 对照组平均表达
  • PREDICTION_RECORDS.csv — 任务列表（还没填预测值）
⬇️
3

🤖 造预测器 + 跑预测

输入：训练集 effect + 待预测任务（第②步产出）
处理：V0 直接平均 / ContextSim 加权平均，对每个测试任务猜 predicted_effect
输出：predicted_effects.npz → 给第④步算特征（包括 model_disagreement）

你造了两个参考预测器（retrieval-style baseline）：

🎯
预测器到底在预测什么？
它不是预测“这个细胞活不活”，也不是预测“哪个基因被敲了”。它预测的是：如果在这个 context 里做这个 perturbation，5000 个基因的表达会怎么变。
输入任务
context = M229 细胞系
perturbation = MAP2K1 敲除
预测器输出
predicted_effect = [0.1, -0.3, 0.0, 0.8, ...]
真实答案
true_effect = 实验真的测出来的变化。最后用来算误差。

V0StrongBaseline

「强基线预测器」

先问：训练集里有没有做过同一个扰动？有的话，把这些历史 effect 拿来平均，作为这次的预测。

人话：以前别人做过 MAP2K1 敲除，我就参考以前 MAP2K1 的平均结果。

ContextSimBaseline

「相似度加权预测器」

也找同一个扰动，但更偏向参考“细胞背景更像”的历史 context。越像，权重越高。

人话：同样是 MAP2K1 敲除，我更相信和 M229 更像的细胞系。

两种预测器的本质区别：直接平均 vs 加权平均

两者做的事本质一样——参考历史上做过同一扰动的结果。区别在于"怎么参考"：

以"预测 M229 × MAP2K1 敲除"为例

训练集里有 3 个背景做过 MAP2K1 敲除：

训练任务背景和 M229 像吗？基因1 的 effect
任务 AA375（黑色素瘤）0.92 很像+0.3
任务 BM249（黑色素瘤）0.88 很像+0.2
任务 CK562（白血病）0.42 不太像+0.5

V0 直接平均

(0.3 + 0.2 + 0.5) / 3 = 0.333

三个人说的话同等重要，不挑人。

ContextSim 加权平均

权重 = 0.42 + 0.39 + 0.19 = 1.0
0.3×0.42 + 0.2×0.39 + 0.5×0.19 = 0.299

和你像的人（A375、M249）声音更大，不像的人（K562）声音被压低。

加权平均的 4 步拆解

① 算相似度
M229 的 control 向量和每个训练 context 的 control 向量算余弦相似度
② 相似度 → 权重
相似度 0.92 → 权重 0.92
然后归一化使权重和 = 1
③ 加权平均
每个历史 effect × 对应权重，再求和
④ 对 5000 个基因都做
得到一条 5000 维 predicted_effect 向量

为什么需要两种不同思路？

🎯
为了产生分歧信号（model_disagreement）。
两个方法思路不同 → 答案有差异 → SafeConf 用这个差异来判断可信度：
差异小 = 两种思路都同意 = 可信度高；差异大 = 有争议 = 可信度低。
就像两个医生诊断一样你放心，诊断完全不同你就慌。
🔌
也可以接更多预测器。PredictorAdapter 的意思是：不管你里面是 GEARS、scGPT，还是别的模型，只要最后能按 SafeConf 要求吐出 predicted_effect 表，就能接进来。
当前代码里已经有 GEARS adapter 的实现文件，但主表没有把 GEARS 当正式主验证结果使用。

产出：predicted_effects.npz + 更新 PREDICTION_RECORDS.csv

🔍 计算特征（质检线索）

输入：训练集历史 + predicted_effect（第②③步产出）
处理：对每条预测提取质检线索（相似度、支持数、分歧、幅度等）
输出：ConfidenceFeatures.csv → 给第⑤步套公式打分

运行 run_fast_feature_scoring.py，提取每条预测的"体检指标"：

context_similarity_max
目标 context 和训练集里最像的 context 有多像？
只需要对照组（control）向量
perturbation_support_count
这个扰动在训练集里有几个背景研究过？
只需要任务表
model_disagreement_rmse
两个预测器对这道题的答案差多少？吵架越凶 → 越不确定
需要两个预测器
historical_residual_risk
类似的扰动在训练集的其他背景上出错多吗？
需要训练集真值
prediction_l2_norm
预测的效应幅度有多大？
需要预测器输出
perturbation_effect_stability
同一扰动在不同背景下效果稳不稳？
需要训练集真值

第 4 步的输入→处理→输出

特征它问的问题需要什么输入人话例子
context_similarity_max 目标细胞背景和训练集里最像的背景有多像？ 训练集 control 向量 + 目标 context 的 control 向量 M229 和训练集里哪个细胞系最像？像不像？
perturbation_support_count 这个扰动以前在几个背景里见过？ 训练集任务表 MAP2K1 敲除以前在 5 个细胞系里做过，还是只做过 1 次？
model_disagreement_rmse 两个预测器给的答案差多远？ V0 的 predicted_effect + ContextSim 的 predicted_effect 两个预测器答案差不多 = 比较稳；差很大 = 不确定
historical_residual_risk 类似任务以前是不是经常错？ 训练集 true_effect + 训练集预测误差 以前类似 perturbation 经常翻车，这次也要小心
prediction_l2_norm 预测的整体变化幅度有多大？ 预测器输出 predicted_effect 5000 个基因整体动静很大，可能更容易错
perturbation_effect_stability 同一个扰动在不同背景下效果稳不稳？ 训练集 true_effect 同一扰动在不同细胞里反应差很多，就更难预测

所有特征输出到同一个文件：ConfidenceFeatures.csv

🔒
防泄漏铁律 L4：所有特征计算只能用 fold 训练集的统计量，绝不偷看测试集的真实答案。

顺手把 magnitude 讲清楚

预测器输出一串变化
predicted_effect = [0.2, -0.1, 0.0, 1.3, ...]
magnitude 问的是整体动静多大
不是看某一个基因，而是看这一整串变化的总幅度。
为什么它会变成强 baseline
模型预测“动静越大”，通常越容易错。审稿人会问：你是不是只是在看动静大小？
predicted_effect = [0.2, -0.1, 0.0, 1.3]
magnitude ≈ 这串数字的整体长度
人话：模型觉得这个扰动会把细胞搅动得多厉害

产出：CONFIDENCE_FEATURES.csv

📐 定义打分公式（Frozen v0.2）

把上面的特征组合成一个分数。公式在看到测试集答案之前就锁死了：

输入：ConfidenceFeatures.csv（第④步产出）
处理：对每个特征做 z-score 标准化，然后加减合并成一个分数
输出：ConfidenceScores.csv（每条预测一个分数） → 使用者用来做决策
Gene-main 数据集（基因扰动类）
score = z(context_similarity) + z(log_support) - z(disagreement)
Chem-robust 数据集（药物扰动类）
score = z(log_support) - z(disagreement)
z = (当前值 - 训练集中位数) / 训练集 IQR
用 median/IQR 而不是 mean/std → 对异常值更鲁棒，不会被极端值拉偏
🧊
Frozen = 冻结 = 不许改。公式定好之后，不管测试集结果好不好，都不回头调权重。这是科学诚信的底线——你不能看到答案再改公式。
⬇️

🧑‍🔬 角度 B — 使用者的 4 步流程

假设你（创造者）已经发表了论文、开源了代码。另一个研究者怎么用 SafeConf？

1

📁 准备数据

使用者需要准备什么？

需要 1：自己的历史扰动数据
可以是 h5ad，也可以是已经提炼好的 effect 表。
关键是：训练集里要有真实扰动效果。
需要 2：自己的预测结果
每个任务一个 predicted_effect。
例：某 cell line + 某 perturbation 的 5000 维预测向量。
得到：风险分数表
SafeConf 输出 CSV。
告诉你哪些预测更值得先做湿实验验证。
材料使用者是否需要？为什么
你的论文 h5ad 原始文件 不需要 那是你用来证明 SafeConf 的公开数据，不是别人使用 SafeConf 的必要输入。
使用者自己的 h5ad 或 effect 表 需要 SafeConf 需要从训练集历史里算 support、context similarity、historical risk。
使用者自己的预测结果 predicted_effect 需要 SafeConf 要给这些预测打分。
测试集真实答案 true_effect 打分时不需要 只有验证 SafeConf 准不准时才打开。真实使用时，正是因为还没做实验，所以不知道答案。
⚠️
边界说明：如果使用者只有一个模型预测表，完全没有任何历史真实扰动效果，当前 SafeConf 不能完整运行。未来可以靠“全局参考数据库”解决，但这不是当前论文已经完成的东西。
⬇️
2

🤖 跑预测器

使用者有两个选择：

方案 A：用 SafeConf 自带的

V0StrongBaseline + ContextSimBaseline，直接运行代码即可。

方案 B：用自己的模型

GEARS、scGPT 等，需要写一层 adapter，把模型输出整理成 SafeConf 认识的 predicted_effect。

问题准确回答
PredictorAdapter 实现了吗？接口和 GEARS adapter 文件已经有，但 GEARS 没有进入 7 主表正式结论。
使用者一定要自己写 adapter 吗？如果用 SafeConf 自带 V0/ContextSim，不需要；如果接自己的深度模型，需要。
adapter 做什么？把任何模型的输出统一变成 predicted_effect，后面 SafeConf 才能算 disagreement、误差和分数。
⬇️
3

📊 SafeConf 打分

运行打分代码，得到每条预测的可信度分数：

A375 x BRAF
+1.5
高可信 → 先用这个结果
A375 x ACSL3
+0.3
中等 → 看情况决定

🎯 做决策——省钱！

使用者根据分数排序做决策：

💬 "我有 1000 条预测，湿实验验证一条要 5000 元。"

💬 "SafeConf 说后 100 条是高风险。"

这就是 prediction triage（预测分诊）——把有限的实验预算花在最该验证的地方。

🧬 图 C — 一条数据从出生到打分的完整旅程

以 Frangieh 数据集、fold 0、任务 M229 x MAP2K1 为例，跟着一条数据走完全程：

1

🔬 实验室做实验

实验者对 M229 细胞系做了 MAP2K1 基因敲除，测了单细胞表达 → 写入 h5ad 文件
2

📥 创造者下载 + 预处理

算出 true_effect = 扰动组平均 - 对照组平均 → 存入 true_effects.npz
算出 M229 的对照组（control）向量 → 存入 target_control_means.npz
3

✂️ 切分数据

这条任务被分到 fold 0 的测试集 → true_effect 被锁起来，预测器看不到
4

🤖 V0StrongBaseline 预测

在训练集里找所有 MAP2K1 扰动，算平均 effect → 这就是 V0 对 M229 x MAP2K1 的 predicted_effect
5

🤖 ContextSimBaseline 预测

在训练集里找和 M229 相似的 context，用 cosine similarity 加权平均它们的 MAP2K1 effect 当预测
6

🔍 提取特征

context_similarity: M229 和训练集最像的 context → 0.72
support_count: MAP2K1 在训练集有 3 个背景 → 3
model_disagreement: V0 和 CS 的预测差 → RMSE = 0.08
7

📐 套公式打分

z = (当前值 - 训练集中位数) / 训练集 IQR

z_ctx = (0.72 - 0.60) / 0.25 = +0.48（比一半以上训练样本更像 → 好信号）
z_support = (log(4) - 1.0) / 0.5 = +0.77（研究得比较多 → 好信号）
z_disagreement = (0.08 - 0.05) / 0.03 = +1.0（预测器分歧大 → 坏信号）

分数 = 0.48 + 0.77 - 1.0 = +0.25（中等偏上）
8

✅ 验证（只有创造者做）

打开测试集真值 → 算 true_error_rmse = 0.089
看 SafeConf 分数 +0.25 和真实误差 0.089 是否匹配 → 在 100 条预测里做排序相关 → rho = 0.45 → 有效
📝
注意：上面第 7 步的具体数字（0.72, 0.60, 0.25 等）是为了演示造的，不是真实值。但流程和公式是真的。

🔢 图 F — 预测器是不是越多越好？

预测器数量能算哪些 SafeConf 线索？当前论文怎么处理？准确说法
1 个预测器 🤖 可以算 context_similarity、support、prediction magnitude。
不能算 model_disagreement。		 当前 frozen v0.2 没有正式单预测器 fallback。 不是不能做，但当前论文没有把它作为主结果。
2 个预测器 🤖🤖 可以算完整 v0.2 所需线索，尤其是 model_disagreement。 这是当前 7 主表的默认配置：V0 + ContextSim。 当前主结论只对这个设置最扎实。
3+ 个预测器 🤖🤖🤖 可以算更多 pairwise disagreement，理论上信息更丰富。 属于未来扩展，不是 frozen v0.2 主结论。 可以说“有扩展空间”，不能说“当前已经证明越多越好”。
自适应权重 不同预测器、不同数据集给不同权重。 这是 learned model / 未来版本方向。 不能混进 frozen protocol，否则会破坏“冻结公式”叙事。
💡
结论：不是预测器越多就自动更好。更多预测器可能提供更多“不确定性线索”，但也会让协议更复杂。
当前论文最稳的说法是：SafeConf v0.2 在两个 retrieval-style 预测器上验证。
