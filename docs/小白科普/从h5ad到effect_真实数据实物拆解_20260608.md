## 0. 先看总变化

SafeConf 这条线的数据大概这样变：

```text
h5ad 原始单细胞数据
  ↓
按 context × perturbation 分组
  ↓
true_effect 向量
  ↓
预测器给 predicted_effect 向量
  ↓
PredictionRecord：一行 = 一次预测 + 真实误差
  ↓
CONFIDENCE_FEATURES：一行 = 这次预测的质检线索
  ↓
CONFIDENCE_SCORES：一行 = 某个打分器给这次预测的分数
  ↓
EVAL 表：统计分数和真实误差是否相关
```

你先记住一句话：

> h5ad 是“原始实验仓库”；PredictionRecord 是“预测答卷”；CONFIDENCE_FEATURES 是“质检线索”；CONFIDENCE_SCORES 是“质检分”；EVAL 是“考试成绩”。

### 0.1 每一步“一行”代表什么

这张表很重要。你最容易乱的地方不是公式，而是“现在这一行到底代表一个细胞，还是一个任务，还是一次预测”。

| 阶段 | 文件/对象 | 一行代表什么 | McFarland 例子里的规模 | 你脑子里的画面 |
| --- | --- | --- | ---: | --- |
| 原始细胞 | h5ad 的 `obs` | 一个单细胞 | 154,710 行 | 每个细胞一张身份证 |
| 原始表达 | h5ad 的 `X` | 一个细胞 × 一个基因的表达量 | 154,710 × 32,738 | 巨大的数字矩阵 |
| 分组任务 | `context × perturbation` | 一个背景里的一种扰动 | 约 1,163 个 unique task | 一道考试题 |
| 切分表 | `HELDOUT_PAIR_SPLITS.csv` | 一个 task 在某个 fold 里属于 train/val/test | 5,815 行 | 考试分卷表 |
| 真实答案 | `true_effects.npz` | 一个 5000 维真实效应向量 | 11,630 个 key | 每题的标准答案向量 |
| 预测答案 | `predicted_effects.npz` | 一个 5000 维预测效应向量 | 11,630 个 key | 预测器交上来的答案向量 |
| 预测记录 | `PREDICTION_RECORDS.csv` | 一个预测器对一个 task 的一次预测 | 11,630 行 | 答卷目录 |
| 质检线索 | `CONFIDENCE_FEATURES.csv` | 同一条预测的可见线索 | 11,630 行 | 质检员的观察表 |
| 质检分数 | `CONFIDENCE_SCORES.csv` | 同一条预测被某一种 score 打了一次分 | 116,300 行 | 一张答卷被多个标准打分 |
| 最终统计 | `FORMAL_MAIN_TABLE.csv` | 一个数据集的总体结果 | 7 行 | 论文主表成绩单 |

为什么 `CONFIDENCE_SCORES.csv` 是 116,300 行？

```text
11,630 条 PredictionRecord
每条记录有 10 种 score
所以 11,630 × 10 = 116,300
```

## 2. h5ad 打开后不是一张表，而是三块最重要的东西

`h5ad` 像一个带目录的数据仓库，最重要是：

| h5ad 部分 | 大白话 | 在本项目里的作用 |
| --- | --- | --- |
| `obs` | 每个细胞的说明书 | 告诉你这个细胞来自哪个 cell line、加了什么药、剂量多少 |
| `X` | 表达矩阵 | 每个细胞的每个基因表达量 |
| `var` | 每个基因的说明书 | 告诉你每一列基因是谁 |

### 2.0 h5ad 的真实内部目录树

你问“h5ad 具体是什么样”，最准确的回答是：

> h5ad 是一个 HDF5 文件，内部像文件夹一样分层存数据。

这个 McFarland h5ad 真实打开后，顶层长这样：

```text
McFarlandTsherniak2020__filtered_perturbation_type_drug.h5ad
├── X       # 表达矩阵，真正的大数字矩阵
├── obs     # 每个细胞的标签/元数据
├── var     # 每个基因的标签/元数据
├── layers  # 额外表达矩阵，这个主线通常不用
├── obsm    # 细胞的额外坐标/嵌入，这个主线通常不用
├── obsp    # 细胞之间的图/距离，这个主线通常不用
├── uns     # 非结构化说明信息
├── varm    # 基因的额外矩阵
└── varp    # 基因之间的图/距离
```

再往里看，真实结构是：

| 路径 | 真实形状 | 类型 | 大白话 |
| --- | ---: | --- | --- |
| `X/data` | 591,403,120 | `float32` | 非零表达值。因为矩阵很大且很多位置是 0，所以只存非零数字 |
| `X/indices` | 591,403,120 | `int32` | 每个非零值对应的行/列索引 |
| `X/indptr` | 32,739 | `int32` | 稀疏矩阵的分段指针 |
| `obs/_index` | 154,710 | string | 每个细胞的 barcode |
| `obs/cell_line/categories` | 172 | string | 172 个 cell line 名字 |
| `obs/cell_line/codes` | 154,710 | `int16` | 每个细胞对应哪个 cell line 的编号 |
| `obs/perturbation/categories` | 14 | string | 14 个药物/对照名字 |
| `obs/perturbation/codes` | 154,710 | `int8` | 每个细胞对应哪个 perturbation 的编号 |
| `obs/dose_value` | 154,710 | `float64` | 每个细胞对应的剂量 |
| `obs/time/categories` | 3 | string | 3 类时间标签 |
| `obs/time/codes` | 154,710 | `int8` | 每个细胞对应哪个时间标签的编号 |
| `var/_index` | 32,738 | string | 基因名 |
| `var/ensembl_id` | 32,738 | string | Ensembl 基因 ID |
| `var/ncounts` | 32,738 | `float64` | 每个基因总表达量 |
| `var/ncells` | 32,738 | `int64` | 每个基因出现在哪些细胞里 |

这里有两个小白必须知道的细节。

第一，`X` 不是普通二维 CSV，而是 sparse matrix（稀疏矩阵）：

```text
普通想象：
154,710 × 32,738 的大表，每个格子都存一个数

实际存法：
只存非零表达值 X/data
再用 X/indices 和 X/indptr 告诉电脑这些值应该放回哪个位置
```

为什么这样存？

因为单细胞数据里很多基因在很多细胞中表达是 0。如果每个 0 都存下来，文件会大得离谱。

第二，`cell_line`、`perturbation` 这类文字列，不是每行重复存完整字符串，而是：

```text
categories = 所有可能的名字
codes = 每个细胞对应第几个名字
```

比如逻辑上你看到的是：

```text
cell_line = 22RV1
perturbation = Trametinib
```

底层可能存的是：

```text
cell_line code = 某个编号
perturbation code = 某个编号
```

软件读出来后，才还原成你能看懂的文字。

## 3. 从 h5ad 到 effect task：把很多细胞压成一条效应向量

SafeConf 不会直接拿 154,710 个细胞逐个打分。

第一步是按：

```text
context × perturbation
```

分组。

在 McFarland 里：

```text
context = cell_line
perturbation = drug
```

比如：

```text
22RV1 × Trametinib
```

这就是一个 task（任务）。

大白话：

```text
同一个细胞系 22RV1
同一种药 Trametinib
这一组所有细胞放一起
算它们的平均表达
再减去同一个细胞系里的 control 平均表达
得到 true_effect
```

公式像这样：

```text
true_effect = mean(expression of perturbed cells) - mean(expression of control cells)
```

这里的 `true_effect` 不再是一个细胞，而是一条向量：

```text
5000 genes long
```

也就是 5000 个数字，每个数字代表一个基因被这个扰动改变了多少。

### 3.1 真实小例子：22RV1 × Trametinib 是怎么从细胞变成 effect 的

现在我们不讲抽象流程，直接看一条真实任务：

```text
context = 22RV1
perturbation = Trametinib
```

意思是：

```text
在 22RV1 这个癌细胞系里，加 Trametinib 这个药，会让基因表达怎么变化？
```

在原始 h5ad 里，这个任务不是一行，而是两堆细胞：

| 组 | 条件 | 细胞数 |
| --- | --- | ---: |
| control 组 | `cell_line = 22RV1`, `perturbation = control` | 158 |
| drug 组 | `cell_line = 22RV1`, `perturbation = Trametinib` | 84 |

先看最原始的几行细胞。下面每一行还是一个细胞。

| cell barcode | cell_line | perturbation | dose_value | time | RPLP1 | RPL41 | RPS2 | RPS18 | TMSB10 |
| --- | --- | --- | ---: | --- | ---: | ---: | ---: | ---: | ---: |
| AAAGCAACAATCCAAC | 22RV1 | control | 0.0 | 24 | 128 | 345 | 165 | 111 | 238 |
| AACCATGTCTTTCCTC | 22RV1 | control | 0.0 | 24 | 272 | 605 | 412 | 255 | 485 |
| AAGGAGCAGAGTACCG | 22RV1 | control | 0.0 | 24 | 270 | 595 | 407 | 191 | 403 |
| AAAGTAGAGTTAAGTG-1 | 22RV1 | Trametinib | 0.1 | 24 | 56 | 151 | 67 | 87 | 57 |
| AACACGTGTCGGCATC | 22RV1 | Trametinib | 0.1 | 24 | 143 | 256 | 124 | 175 | 177 |
| AACCATGCATGAAGTA | 22RV1 | Trametinib | 0.1 | 24 | 73 | 114 | 58 | 49 | 79 |

这张表怎么读？

```text
前三行是 22RV1 的 control 细胞
后三行是 22RV1 加 Trametinib 后的细胞
RPLP1/RPL41/... 是基因
数字是这些基因在这些细胞里的表达量
```

然后我们对每一组细胞求平均。这里为了让你看懂，只展示 8 个基因：

| gene | control_mean | trametinib_mean | raw_demo_effect |
| --- | ---: | ---: | ---: |
| RPLP1 | 141.354 | 105.857 | -35.497 |
| RPL41 | 321.772 | 225.667 | -96.105 |
| RPS2 | 186.532 | 128.476 | -58.055 |
| RPS18 | 148.335 | 126.440 | -21.895 |
| TMSB10 | 194.228 | 140.988 | -53.240 |
| MT-CO3 | 124.329 | 83.976 | -40.353 |
| RPS19 | 105.354 | 89.262 | -16.093 |
| MT-CO1 | 167.677 | 115.571 | -52.106 |

这里的计算非常朴素：

```text
raw_demo_effect = trametinib_mean - control_mean
```

例如 `RPLP1`：

```text
105.857 - 141.354 = -35.497
```

这句话的生物学意思是：

```text
在 22RV1 里加 Trametinib 后，RPLP1 这个基因的平均表达比 control 低了 35.497。
```

重要提醒：

> 上面这张表是为了让你看懂“从原始 X 到 effect”的动作，所以用的是 h5ad 里直接抽出来的几个基因做演示。正式 pipeline 后面会经过基因筛选/处理，最终保存成 5000 维 `true_effect` 向量，所以正式文件里常常只看到 `gene_index`，不一定直接带 gene name。

所以从数据变化角度看，这一步就是：

```text
很多行单细胞
  ↓ 求平均
两行 group mean：control_mean 和 drug_mean
  ↓ 相减
一条 effect 向量
```

### 3.2 这一步之后，数据形状发生了什么变化

原来是：

```text
154,710 个细胞 × 32,738 个基因
```

对一个 task 来说，变成：

```text
1 个 context × perturbation task
1 条 true_effect 向量
5000 个数字
```

也就是说：

```text
细胞级数据
  → 任务级数据
```

这一步是整个项目最关键的“压缩”。

## 4. held-out split 长什么样

项目要模拟“有些 context × perturbation pair 没见过”的场景，所以会做 split。

真实 split 表一行长这样：

| dataset_name | task_id | task_key | context | perturbation | fold_id | split | pair_seen_in_train | perturbation_seen_in_train | context_seen_in_train |
| --- | ---: | --- | --- | --- | ---: | --- | --- | --- | --- |
| McFarlandTsherniak2020 | 3 | McFarlandTsherniak2020::task_00003 | 22RV1 | Trametinib | 0 | test | False | True | True |

怎么读：

| 字段 | 意思 |
| --- | --- |
| `context = 22RV1` | 测试背景是 22RV1 这个细胞系 |
| `perturbation = Trametinib` | 测试药物是 Trametinib |
| `split = test` | 这条 task 是考试题，不给预测器训练 |
| `pair_seen_in_train = False` | 训练集中没见过 22RV1 × Trametinib 这个组合 |
| `context_seen_in_train = True` | 训练集中见过 22RV1 这个细胞系 |
| `perturbation_seen_in_train = True` | 训练集中见过 Trametinib 这个药 |

这就是 held-out pair split（留出组合切分）的核心：

> 单独的细胞系见过，单独的药也见过，但这个细胞系+这个药的组合没见过。

## 5. PredictionRecord 长什么样

当预测器对一个 test task 做预测后，就会生成一行 `PredictionRecord`。

真实例子：

| record_id | task_id | task_key | dataset_name | fold_id | split | context | perturbation | predictor_name | true_effect_key | predicted_effect_key | true_error_rmse | true_error_cosine | true_error_top20 |
| --- | ---: | --- | --- | ---: | --- | --- | --- | --- | --- | --- | ---: | ---: | ---: |
| v2_rec_000930 | 3 | McFarlandTsherniak2020::task_00003 | McFarlandTsherniak2020 | 0 | test | 22RV1 | Trametinib | V0StrongBaseline | v2_rec_000930::true_effect | v2_rec_000930::predicted_effect | 0.5776 | 0.1539 | 0.35 |

怎么读：

| 字段 | 意思 |
| --- | --- |
| `record_id` | 这一条预测记录的 ID |
| `context` | 在哪个背景/细胞系里预测 |
| `perturbation` | 预测哪个扰动/药物 |
| `predictor_name` | 哪个预测器做的预测 |
| `true_effect_key` | 真实答案向量在 `true_effects.npz` 里的 key |
| `predicted_effect_key` | 预测向量在 `predicted_effects.npz` 里的 key |
| `true_error_rmse` | 预测向量和真实向量之间的 RMSE，越大说明预测越差 |

这个文件的规模：

| 文件 | 行数 | 列数 |
| --- | ---: | ---: |
| `PREDICTION_RECORDS.csv` | 11,630 | 15 |

### 5.1 同一条记录的路线卡

从这里开始，我们一直追同一条记录：

```text
record_id = v2_rec_000930
```

它的完整路线是：

| 步骤 | 看到的数据 | 这一刻发生了什么 |
| --- | --- | --- |
| 1 | `HELDOUT_PAIR_SPLITS.csv` 里 `22RV1 × Trametinib` 是 `test` | 这道题不给训练，作为考试题 |
| 2 | `pair_seen_in_train = False` | 训练集中没见过 `22RV1 × Trametinib` 这个组合 |
| 3 | `context_seen_in_train = True` | 训练集中见过 `22RV1` 这个细胞系的其他药物 |
| 4 | `perturbation_seen_in_train = True` | 训练集中见过 `Trametinib` 这个药在其他细胞系里的效果 |
| 5 | `V0StrongBaseline` 输出 `predicted_effect` | 预测器根据训练集历史，猜一个 5000 维效应向量 |
| 6 | 真实实验数据给出 `true_effect` | 这是标准答案，但打分时不能偷看 |
| 7 | 比较 `predicted_effect` 和 `true_effect` | 得到 `true_error_rmse = 0.5776` |
| 8 | SafeConf 计算 `CONFIDENCE_FEATURES` | 用允许看的线索判断这次预测靠不靠谱 |
| 9 | 多个 score 给它打分 | 例如 `simple_combined_confidence = -0.8523` |
| 10 | 最后进 EVAL | 和其他 test records 一起统计 Spearman ρ / partial ρ |

这里有个特别重要的点：

> V0StrongBaseline 可以用训练集里别的细胞系的 Trametinib 历史信息，但不能用 `22RV1 × Trametinib` 这道 test 题自己的真实答案。

所以这不是“拿答案抄答案”，而是：

```text
看过 22RV1 的其他药
也看过 Trametinib 的其他细胞系
但没看过 22RV1 × Trametinib 这个组合
```

## 6. 向量到底是什么：true_effect 和 predicted_effect 具体长什么样

你可以把 vector（向量）先理解成：

> 一串有固定顺序的数字。

在这里，一条 effect vector（效应向量）有 5000 个数字：

```text
gene_index:       0       1       2       3       4       ...       4999
true_effect:   [ 0.0,    0.0,    0.0,    0.0056, 0.0,    ...       ?    ]
```

每个位置代表一个基因。

为了简化文件，正式 `true_effects.npz` 里常用 `gene_index = 0,1,2,...`，不一定直接写出基因名。你先不用纠结第 4027 个基因到底叫什么。你先理解：

```text
第 4027 个位置的数字
= 第 4027 个基因在这个 task 下的表达变化
```

### 6.1 同一条记录的两个向量

我们继续追同一条预测：

```text
record_id = v2_rec_000930
context = 22RV1
perturbation = Trametinib
predictor = V0StrongBaseline
```

这条记录有两个 5000 维向量：

| 向量 | 来自哪里 | 是否允许 SafeConf 打分时看 |
| --- | --- | --- |
| `true_effect` | 真实实验数据算出来的答案 | 不允许。只能最后评估时看 |
| `predicted_effect` | V0StrongBaseline 预测器猜出来的答案 | 允许。预测器输出本来就是要被质检的对象 |

前 12 个位置长这样：

| gene_index | true_effect | predicted_effect | difference = pred - true | squared_error |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | -0.00001649 | -0.00001649 | 0.000000000272 |
| 1 | 0 | 0 | 0 | 0 |
| 2 | 0 | 0 | 0 | 0 |
| 3 | 0.005576 | -0.001504 | -0.007079 | 0.0000501 |
| 4 | 0 | -0.0001104 | -0.0001104 | 0.0000000122 |
| 5 | -0.01341 | -0.0006788 | 0.01273 | 0.000162 |
| 6 | 0 | 0 | 0 | 0 |
| 7 | 0 | 0.000004795 | 0.000004795 | 0.000000000023 |
| 8 | -0.25 | -0.2186 | 0.03137 | 0.000984 |
| 9 | 0.01190 | -0.003585 | -0.01549 | 0.000240 |
| 10 | 0 | 0 | 0 | 0 |
| 11 | 0 | 0.000132 | 0.000132 | 0.0000000174 |

这张表的含义非常直接：

```text
true_effect       = 标准答案
predicted_effect  = 预测答案
difference        = 预测答案 - 标准答案
squared_error     = difference 的平方
```

### 6.2 为什么只看前 12 个位置还不够

前 12 个位置很多接近 0，看起来误差不大。但真正 RMSE 是用全部 5000 个位置算的。

这条记录中，误差最大的 10 个位置是：

| gene_index | true_effect | predicted_effect | difference | squared_error |
| ---: | ---: | ---: | ---: | ---: |
| 4027 | -53.240 | -28.664 | 24.576 | 603.957 |
| 1989 | -17.188 | -1.263 | 15.925 | 253.595 |
| 1900 | -5.616 | 8.324 | 13.940 | 194.328 |
| 564 | -15.828 | -7.514 | 8.314 | 69.125 |
| 490 | -6.714 | -0.506 | 6.208 | 38.536 |
| 2915 | -7.709 | -1.737 | 5.972 | 35.667 |
| 1902 | -6.488 | -0.911 | 5.577 | 31.099 |
| 1966 | -0.292 | -5.378 | -5.087 | 25.875 |
| 3761 | -11.236 | -6.201 | 5.035 | 25.350 |
| 924 | -4.249 | 0.662 | 4.911 | 24.120 |

这里你就能直观看到：有些基因位置预测偏差非常大。

### 6.3 RMSE 是怎么来的

RMSE 的全称是 root mean squared error（均方根误差）。

公式是：

```text
RMSE = sqrt(mean((predicted_effect - true_effect)^2))
```

按人话分四步：

```text
第 1 步：每个基因位置上，predicted_effect - true_effect
第 2 步：把差值平方，避免正负抵消
第 3 步：5000 个平方误差求平均
第 4 步：开平方，回到原来的量纲
```

这条记录用全部 5000 个位置算出来：

```text
true_error_rmse = 0.5776326656
```

在 `PREDICTION_RECORDS.csv` 里四舍五入显示为：

```text
0.5776
```

关键点：

> SafeConf 打分时不能偷看 `true_effect`，所以也不能偷看 `true_error_rmse`。`true_error_rmse` 是最后考试结束后才揭晓的成绩。

## 7. CONFIDENCE_FEATURES 长什么样

PredictionRecord 只是“答卷”。接下来 SafeConf 要给这张答卷找质检线索。

同一条 `v2_rec_000930` 的 features 长这样：

| record_id | fold_id | split | context | perturbation | predictor_name | context_similarity_max | context_similarity_mean | perturbation_support_count | perturbation_effect_variance | prediction_l2_norm | prediction_abs_mean | prediction_magnitude_deviation | model_disagreement_rmse | historical_residual_risk |
| --- | ---: | --- | --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| v2_rec_000930 | 0 | test | 22RV1 | Trametinib | V0StrongBaseline | 0.9677 | 0.8084 | 121 | 8.709 | 47.92 | 0.1069 | 0.7474 | 0.3692 | 2.213 |

怎么读：

| feature | 大白话 |
| --- | --- |
| `context_similarity_max` | 当前背景和训练集中最像的背景有多像 |
| `perturbation_support_count` | 训练集中这个药/扰动有多少历史支持 |
| `prediction_l2_norm` | 预测出来的效应向量幅度有多大 |
| `prediction_magnitude_deviation` | 这个预测幅度是否偏离正常范围 |
| `model_disagreement_rmse` | 两个预测器之间差得多不多 |
| `historical_residual_risk` | 历史上类似情况残差风险有多高 |

这个文件的规模：

| 文件 | 行数 | 列数 |
| --- | ---: | ---: |
| `CONFIDENCE_FEATURES.csv` | 11,630 | 24 |

注意：

```text
PredictionRecord 一行
对应 CONFIDENCE_FEATURES 一行
```

也就是说，它们是一一对应的。

### 7.1 这些 feature 到底从哪里来

同一行 feature 不是凭空出现的。它们来源不同：

| feature | 来源 | 是否看了 test 的真实答案 | 对 `v2_rec_000930` 的具体意思 |
| --- | --- | --- | --- |
| `context_similarity_max = 0.9677` | 训练集里的 control/baseline 表达相似度 | 不看 | 22RV1 和训练集中最像背景的相似度很高 |
| `context_similarity_mean = 0.8084` | 训练集背景相似度均值 | 不看 | 22RV1 和训练集背景总体也比较像 |
| `perturbation_support_count = 121` | 训练集中同扰动的历史任务数 | 不看 | 训练集里有 121 个可参考的 Trametinib 相关背景 |
| `prediction_l2_norm = 47.92` | 预测器输出的 `predicted_effect` | 不看 | V0 预测出来的效应向量幅度 |
| `prediction_magnitude_deviation = 0.7474` | 预测幅度和训练集常见幅度比较 | 不看 | 这条预测的幅度偏离程度 |
| `model_disagreement_rmse = 0.3692` | V0 和 ContextSim 两个预测器输出之间的差 | 不看 | 两个预测器对这道题分歧多大 |
| `historical_residual_risk = 2.213` | 训练集历史残差模式 | 不看 test 答案 | 类似历史情况中风险偏高 |

你可以把它理解成质检员只允许看这些东西：

```text
1. 这道题像不像训练集里的题？
2. 这个药以前见过多少次？
3. 预测器给出的答案幅度是不是异常？
4. 两个预测器意见是否一致？
5. 历史上类似情况容易错吗？
```

质检员不允许看：

```text
true_effect
true_error_rmse
```

所以 SafeConf 不是“看答案后解释答案”，而是“答案揭晓前先打可信度分”。

### 7.2 v0.2 公式在这一步怎么用

frozen protocol v0.2（冻结协议）有两条主线：

| dataset family | 公式大意 | 适用 |
| --- | --- | --- |
| `gene_main` | `context_similarity + log_support - model_disagreement` | 基因扰动/基因主线 |
| `chem_robust` | `log_support - model_disagreement` | 化学药物主线 |

McFarland 属于 `chem_robust`，所以主公式大意是：

```text
支持越多 → 越可信
模型分歧越大 → 越不可信
```

对应这条记录：

```text
support_count = 121        # 支持很多，是正面线索
model_disagreement = 0.369 # 两个预测器有一定分歧，是负面线索
```

然后公式会把这些 feature 做标准化，再组合成一个 confidence/risk score。

## 9. 最后 EVAL 表长什么样

EVAL 的问题很简单：

> 分数越高/越低，真实误差是不是按预期变化？

McFarland 这个数据集的正式主表结果是：

| dataset_name | dataset_family | score_name | n | aligned_rho | magnitude_only_rho | partial_rho_control_magnitude | risk_coverage80_improve_pct | n_bootstrap |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| McFarlandTsherniak2020 | chem_robust | protocol_v0_2_family_confidence | 2326 | -0.08593 | 0.7954 | -0.06092 | 3.951 | 1000 |

怎么读：

| 指标 | 意思 |
| --- | --- |
| `aligned_rho` | 分数和真实误差方向对齐后的 Spearman 相关 |
| `magnitude_only_rho` | 只靠效应幅度这个基线能做到多少 |
| `partial_rho_control_magnitude` | 控制效应大小后，SafeConf 分数还剩多少独立信号 |
| `risk_coverage80_improve_pct` | 只保留高可信 80% 后，误差改善多少 |

McFarland 的结论：

```text
aligned_rho = -0.08593
partial_rho = -0.06092
```

这说明 frozen v0.2 在 McFarland 上失败了，而且是诚实保留的 failure boundary（失败边界）。

但单特征/学习型分数里仍有信号：

| score_name | score_type | n | direction_aligned_spearman | risk_cov_80_improve_pct |
| --- | --- | ---: | ---: | ---: |
| learned_risk_score | risk | 2326 | 0.5872 | 18.38 |
| historical_residual_risk | risk | 2326 | 0.4258 | 16.47 |
| model_disagreement_risk | risk | 2326 | 0.1518 | 5.242 |
| simple_combined_confidence | confidence | 2326 | 0.1862 | 6.953 |

这段很关键：

> McFarland 不是“数据完全没信号”，而是“frozen v0.2 这个提前固定的公式没抓住正确信号组合”。

论文里应该写成失败边界和讨论，不应该为了救它临时改公式。

## 11. 最容易混的 4 件事

### 11.1 `obs` 不是 PredictionRecord

`obs` 是单细胞级别：

```text
一行 = 一个细胞
```

`PredictionRecord` 是预测任务级别：

```text
一行 = 一个预测器对一个 context × perturbation task 的一次预测
```

它们不是同一种东西。

### 11.2 `X` 不是 true_effect

`X` 是表达矩阵：

```text
细胞 × 基因
```

`true_effect` 是从 `X` 里按组算出来的：

```text
扰动组平均表达 - 对照组平均表达
```

### 11.3 `true_error_rmse` 不是 SafeConf 打分

`true_error_rmse` 是答案揭晓后才能算的真实误差。

SafeConf 打分时不能看它。

### 11.4 `confidence` 和 `risk` 方向相反

```text
confidence 越高，预测越可信，误差应该越低
risk 越高，预测越危险，误差应该越高
```

所以评估时要做 direction alignment（方向对齐）。

## 13. 一句话收束

你现在不用先懂所有生物学，也不用先懂所有代码。

你先把这一条数据链看懂：

```text
一个细胞表达矩阵 X
  → 一个 context × perturbation 的 true_effect
  → 一个预测器的 predicted_effect
  → 一条 PredictionRecord
  → 一行 ConfidenceFeatures
  → 多行 ConfidenceScores
  → 一个数据集级别的 rho / partial rho / RC@80%
```

这条链通了，SafeConf 这个项目的主体你就通了。
