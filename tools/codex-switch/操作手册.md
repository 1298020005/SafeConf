# 操作手册

## 账号

| 命令 | 账号 |
|:-----|:-----|
| `codex-switch 350` | 3506725328@qq.com |
| `codex-switch 348` | 3485725367@qq.com |

等价：`codex-account use qq3506725328`（已对接 `codex-switch`）。

## 切号（3 步）

1. SSH 执行：`codex-switch 350`（或 `348`）
2. Cursor：**Developer → Reload Window**，等 ~20s
3. 打开 Codex，发一句测试

## 看当前号

```bash
cat ~/.codex-active
codex-cursor-proxy login status
```

## 网络要先通

```bash
~/bin/proxy-healthcheck.sh
```

失败：Windows 开 Clash **7897** → 重连 Cursor SSH（隧道 **17897**）→ 再跑上面命令。

## 数据在哪

- 会话 / 索引：**一个目录** `~/.codex`
- 两号登录快照：`~/.codex-profiles/qq3485725367/auth.json`、`.../qq3506725328/auth.json`
- 旧分目录备份：`~/.codex-accounts/`（日常不用）

## 重新登录某号

```bash
CODEX_HOME=~/.codex-profiles/qq3506725328 \
  ~/.local/lib/node_modules/@openai/codex/bin/codex.js login --device-auth
cp ~/.codex-profiles/qq3506725328/auth.json ~/.codex/auth.json   # 若当前正在用 350
```

## 风控（简）

- 切号间隔 ≥10 分钟，勿连切
- 勿从 Windows Cockpit **频繁拷贝** auth 到服务器
- 勿只改 `auth.json` 而拆散统一数据目录（已用 `codex-unify-data` 合并过）

## 回滚统一数据

```bash
ls ~/archives/codex-backups/unify-*
# 按 RESTORE 说明解压 accounts.tar.gz / codex-dot.tar.gz（见 archives/codex-backups/20260523-213717-full/RESTORE-说明.md）
```
