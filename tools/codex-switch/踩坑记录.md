# 踩坑记录

| 现象 | 原因 | 处理 |
|:-----|:-----|:-----|
| 远程 Codex 无响应 / 空云 | Extension Host 代理 **7897** 或隧道未建 | Remote 用 **17897**；Clash 7897 + 重连 SSH |
| `fetch failed` wham/cloud | 同上 | `proxy-healthcheck.sh` |
| 日志里 `C:\...\codex.exe` | 本机 User `cliExecutable` 覆盖远程 | Remote scope 设 `codex-cursor-proxy` |
| `remote port forwarding failed 17897` | 端口已被 Cursor 占用 | **忽略**；`ss \| grep 17897` 有监听即可 |
| 历史「全没了」 | 只看当前 symlink 目录；或 sqlite 重建 | 数据在 `~/.codex-accounts` / 备份；合并或 unify |
| 本机有历史、服务器没有 | **无跨机同步** | 同号登录 backfill，或手动拷 `sessions` |
| 切号后会话乱/打不开 | 只换 auth、sessions 属于另一 `account_id` | 用 **统一目录+profiles**；跨号旧线程可能只能看不能续聊 |
| Cockpit 拷 auth 后官方不认 | 缺 `auth_mode` 或非 managed 登录链 | 服务器用 `codex login --device-auth` 各登一次 |
| 两机同时刷同一 refresh | Windows Cockpit 与服务器交替切同一号 | 错开时间；各环境独立登录 |
| `sync-codex-auth` 只链 auth | auth 与 sqlite/sessions 不一致 | 已废弃；用 `codex-switch` / unify |
| `NODE_OPTIONS` 注入 fetch 补丁 | 过度工程、易崩 | 已从 extensionHost.env 移除 |
| `mcp_request_timeout` | app-server 卡死 / 代理瞬断 | `pkill -f 'codex app-server'` + Reload |
| `registerChatSessionItemProvider is not a function` | Cursor 与扩展 API 版本差 | 升级 Cursor；一般非致命 |
| 中间云图标 | 常 = **云任务为空**，非加载失败 | `codex cloud list` → No tasks |
| 350 vs 348 面板条数不同 | 当时 symlink 只指一个目录 | 现已 unify，切号只换登录 |

## 勿做

- 生产环境长期 **两个号共用一个目录只换 auth**（未 unify 前）
- 几分钟内 **348↔350 连切**
- 从 Windows **反复覆盖** 服务器 `auth.json`
- 在服务器再开 **7897→17897** 转发脚本（与 Cursor 隧道重复）
